# 写入与运行细节

仅用于用户要求的实际操作。先确认当前提供的工具和准确项目的本机授权；解释、审查或诊断保持只读。用户已授权的任务继续推进，遇到新权限或实质范围扩张才确认。

## 按执行环境选择终端

在 Codex 桌面端或其他使用本机执行环境的 Codex 会话中，只使用 Codex 自带本机终端执行命令、启动服务、安装依赖和访问数据库 CLI；不得调用 CoLink 的 `terminal_*` 或 `execution_*`，包括以查询、固定数据库读取或隔离执行代替本机终端。本机终端不可用时说明限制，不自动回退到 CoLink 终端。CoLink 源码读取、代码智能和受控源码修改可按原授权继续使用。

本文件的固定数据库读取、原生开发终端和可选隔离执行流程只适用于非 Codex 本机环境；不得据此要求 Codex 本机操作先切换 CoLink 档位。Codex 本机操作仍遵守当前会话的用户授权和工具限制。

## 受控源码修改

1. 用 `write_task_status` 确认状态，从返回中取得开始任务所需的一次性请求标识，按实际 schema 调用 `begin_write_task`。相关活跃任务可继续复用；大型任务声明准确相对路径及需要创建的各级父目录，不以依赖图扩大可写范围。
2. 读取目标原文及完整 SHA。搜索带 context 时附带真实文件 sha256/size；原文已覆盖所需范围且未截断，可直接用于这笔写入，缺必要原文则继续精确读取。`apply_edit` 使用实际 `expected_sha256`，插入传 `expected_context`，行范围替换传 `old_text`，片段替换要求唯一匹配；考虑真实 LF / CRLF 行号。服务保存恢复材料、校验写入并读回，不自创额外备份协议。
3. `create_directory` 先创建已声明父目录，`create_file` 不覆盖已有对象。删除仅在用户要求且 `delete_file` 可用时，传准确单个路径和当前完整 SHA；不以空文件冒充删除，不推断支持重命名或递归删除。
4. 每个不同操作使用新 `request_id`；同一操作重试保持原标识和全部相同参数。响应丢失先查询任务状态；不要换标识重复插入、创建或删除。`REQUEST_ID_CONFLICT` 是参数绑定冲突，不能当作普通源码冲突忽略。
5. 成功后刷新读取上下文，用 `read_code` 读回必要内容。下一笔写入可使用返回的新 SHA，但行号及片段必须对应真实新正文。需要审查整项改动时，用 `analyze_code` 的 `mode=diff` 摘要，再限定 `selector.path` 和 `detail=patch`；Live 比较依赖已有任务材料，不代表任意外部编辑历史。历史 Mirror 的 `get_diff` 仍比较其保留的源码状态，不能混用历史含义。
6. 哈希、原文、属性、授权或容量冲突停止该笔写入，说明实际进度；不更换校验值强写。`WRITE_RECOVERY_REQUIRED` / `WRITE_ROLLBACK_RECOVERY_REQUIRED` 保留任务，由本机受控恢复处理，不在网页自行强制覆盖。
7. 用户功能完成后 `finish_write_task`。写入读回只证明文件已更新，不等于测试或业务验收。源码恢复以用户已保存的 Git 版本为依据；没有记录的内容不保证能恢复，不自行 reset、checkout、clean、stash、提交或模拟整项撤销。工具返回中的版本差异不能当作当前能力。

### 批量编辑与创建

已取得准确原文、哈希及任务范围时，当前 `write_batch(project_id,task_id,request_id,operations)` 可减少多笔独立写调用；operations 为 1–20 项、全批 JSON 最多 8 MiB，同批 path 不重复。每项由 kind 区分：

- `apply_edit`：path、expected_sha256、edit，沿用现有原文和上下文校验；一项只有一个 edit。
- `create_file`：path、content；已有目标不覆盖。
- `create_directory`：path；缺失的每层父目录必须由本批前序显式创建，且在原任务范围内。

每项不传 request_id；稳定子标识由批标识与 index 派生。全批先预检所有未完成项，再使用原协调器逐项保存意图、提交和读回，并持久保留批摘要。批量入口不支持删除、移动、命令或目录扩权。

响应包含 atomic=false、state=completed/partial/blocked、completed_count、total 和逐项 items。执行期间失败可能保留前序成功项，不能称为全批原子成功或全批撤销。先查 `write_task_status` 的最近十个 batches 摘要并刷新实际文件依据；响应丢失或重试时保持批 request_id、任务与 operations 全部不变。服务核验已完成项当前真实文件的身份、哈希与属性，再跳过有效的已完成项；内容变化按冲突处理。不要换标识重发同一整批，也不要改绑定参数追求强行重试；pending 项交由本机恢复。只对真正完成的项报告保存成功，未开始项保持明确。

## 固定数据库读取

准确 `project_id` 调用 `terminal_read_targets`，取得脱敏目标和支持命令，再按 schema 调用 `terminal_read`。使用返回的目标 ID 或项目内已有数据库相对路径，不猜凭据。

读取命令由工具支持范围决定，按需要查库、查表、结构或有限预览。遵守行数、输出和时间限制；首批键及游标不代表全量。识别到配置、端口或客户端不证明登录成功。

只读 / 写入档不提供任意数据库语句、脚本、CLI 参数或数据库修改；认证失败、目标歧义或未解析配置应说明缺项，不改用通用终端绕过档位。数据库写入需要当前项目本机开发授权。

## 原生开发终端

用户要求开发、运行、服务或数据库操作，且项目已开启开发授权时，使用实际提供的 `terminal_*`。`EXECUTION_DISABLED` 时说明本机需要切到开发档，技能不能自行开启。

1. 按需用 `execution_environment` 确认路径和版本，启动服务前用 `port_status` 检查相关端口。使用项目已有运行方法、环境及依赖锁文件，不默认全局安装软件。项目需要隔离依赖时在真实目录创建或复用其本地环境。
2. `terminal_start` 的 `command` 是 argv；需要脚本时按当前 schema 使用 shell 路径。`cwd` 按规则相对真实项目选择。交互 CLI 或长期服务用 `tty=true`；长期服务另用 `service=true`，一次性命令用 `service=false` 和合理的超时。遵守工具实际并发与生命周期限制。
3. 保存 `job_id`，用 `terminal_status` 确认真实状态，再向同一会话 `terminal_input`。提交命令需换行；输入已排队不等于执行完成，继续读取输出。PTY 退出用程序命令或 control-D；`eof` 仅用于非 PTY。
4. 新操作使用新请求 ID；同一操作重试保持 ID 和完整参数。响应丢失先查状态 / 输出，不重复迁移、建库或输入。网页刷新用 `terminal_list` 找回会话，运行时重启不自动重跑旧命令。
5. `terminal_output` 按返回游标续读，报告截断；遵守实际输出和等待上限。区分进程存活、登录成功、迁移完成、应用健康与业务通过。用户指定自行验收时交付步骤，不追加执行其保留的测试。
6. 数据库 CLI / 驱动使用本机真实配置及账户权限完成用户请求的操作，无需旧版 CoLink 数据库登记页。凭据在本机解析，不打印、放进 argv 或写入技能；留意程序主动打印的敏感内容。
7. 空目录项目先检查本机可用环境和数据库认证，再创建所需配置、数据库、迁移与实现。缺有效认证时说明需要什么，不猜密码；只有端口或客户端存在不能宣称可连接。
8. 原生终端直接修改真实文件 / 数据库，不经源码写协调器，也不自动生成完整任务 Diff 或恢复记录。生成器、依赖安装和迁移限定在已授权开发任务；准确说明实际变化，取消不会撤销既有副作用。
9. 停止本工具启动的会话用 `terminal_cancel` 并确认退出。旧服务释放端口使用 `port_release_plan` / `port_release` 的准确进程确认流程，不停止未知进程。本地 Git 提交仅在用户要求时进行，选择本任务文件，不混入其他改动，也不自动推送。

原生终端按当前 macOS 用户权限执行；项目身份只提供授权入口与初始 cwd，不能宣称目录、网络或数据库沙盒。实际目标仍限于用户任务。

## 可选隔离执行

用户有意选择隔离构建 / 测试时，使用 `execution_plan` → 按要求 `execution_rehearse` → `execution_start`，再用对应状态、输出、停止及恢复工具。该路径的输入、网络、端口、socket、预算与受控写回限制仍适用；计划变化重新获取，重试保持请求幂等。

不要把隔离执行限制套到原生终端，也不要据此宣称当前没有交互输入或不能运行普通服务。当前实际工具、用户指定方法和准确项目的权限决定路径。
