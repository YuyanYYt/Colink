## 1. INVALID_STRUCTURE_QUERY 的原因

上一轮调用的 `file_context`、文件路径、`ownership/dependencies` 和 6000 字符预算
均为合法参数。独立源码副本通过相同的 `build_mcp.call_tool` 路径重现了错误：

```text
bound_analysis_result
  → ValueError: one symbol exceeds response budget; choose a larger max_chars
live_index 的通用异常处理
  → INVALID_STRUCTURE_QUERY
MCP SDK 的工具错误包装
  → Error executing tool analyze_code: INVALID_STRUCTURE_QUERY ...
```

问题发生在 CoLink 的响应裁剪与异常分类，不是 MCP 协议失效或调用选择器错误。
原裁剪过程可能在组合关系仍占用预算时耗尽符号页，并错误地判断单符号也无法容纳。

已修改为：

- 符号/候选页至少保留一个可选择的事实，再裁剪其他可移除部分及无用端点；分页位置继续前进。
- 最小有用结果仍装不下时，抛出独立的 `AnalysisResponseBudgetExceeded`，对外返回固定的
  `ANALYSIS_RESPONSE_BUDGET_EXCEEDED` 提示；不回显输入或异常中的源码。
- 参数错误、上下文失效、计算预算和索引不可用保留各自的处理路径。
- 结构、覆盖元数据、显示名称和可选正文继续共享响应字符预算；默认预算没有扩大。

首次修复副本中，同一请求在 6000/12000/20000 字符预算下分别返回
4666/11766/19900 字符的合法部分结果。最终源码的原始请求复核与更多预算检查
保存在本轮验收目录，结果以该目录的最终回执为准。

## 2. 模式与工具暴露

| 来源 | 模式选择 | 工具数量 |
| --- | --- | --- |
| 新开发源码 | 日常 schema 不含 mode；后台兼容原有 13 种显式策略；新增模式 0 种 | 独立只读服务 9、挂接写入协调器 19、完整工作区 40 |
| 当前安装包 | 包内定义仍显式暴露原 mode 参数；本轮未替换安装包 | 实际连接还受权限档位和客户端缓存影响 |
| 历史 Mirror | 保持原接口与快照语义 | 15 个只读工具 |

日常 `analyze_code` 根据选择器按需路由：文件取文件上下文；符号取符号上下文；
一个具体值取来源、影响及结构；两个符号取有向调用路径；两个具体值取值路径。
只选择文件/符号不启动值流，缺少值时不猜参数，重复定义仍返回候选。

后台保留的 13 种策略是 8 种结构策略：`file_context`、`symbol_context`、`callers`、
`callees`、`call_graph`、`call_path`、`class_relations`、`file_dependencies`；
4 种值传播策略：`data_origin`、`data_impact`、`data_path`、`combined`；以及 `diff`。
保留它们用于既有调用、脚本和测试兼容，不增加一组工具，也不在默认 schema 中列出模式枚举。
非法 mode、未知字段和隐式类型转换继续拒绝；其他工具的字段守卫未放宽。

上述数量按服务组件注册方式区分，不等同于授权开关档位。完整工作区即使关闭
写入/开发授权，仍注册这 40 个工具，由调用时权限校验拒绝操作；本轮没有把它
改成按开关动态隐藏工具。旧 mode 的兼容通过服务端及当前 SDK 验证，尚未完成
所有客户端刷新、严格 schema 处理与网页交互验收。

在冻结的 M3 对照中，`analyze_code` 输入 schema 为 3784 → 3492 字符，完整单工具定义
为 6219 → 5719 字符。这个变化没有证明整个 40 工具集合已经精简完，也不能替代
模型选择延迟、Token 或真实网页体验的测量。

## 3. 已有语言与新增结构前端

| 语言 | 结构前端 | 值传播 |
| --- | --- | --- |
| Python | 原有有界定义、绑定和关系 | 原有有界 may-flow |
| Java | 原有结构，并补方法引用的保守声明绑定 | 原有有界 may-flow，动态分派等保持 partial/unknown |
| TypeScript/TSX | 新增有界定义、作用域、类型引用、显式导入导出及直接调用关系 | 明确 unsupported_language |
| JavaScript/JSX/mjs/cjs | 新增同类有界结构；CommonJS 运行时模块关系仍未知 | 明确 unsupported_language |
| Swift/Rust/Vue | 能识别源码语言，结构尚不支持 | 不支持 |

新前端只解析已授权库存中的文本，不执行项目模块、npm 脚本或编译器，不读取目录外
源码，不自动获取第三方库。相对路径必须有唯一目标；同名候选、动态对象、路径别名、
裸包、通配重导出及框架语义保留未知或部分覆盖。

Java `Type::method` 和带声明类型 receiver 的方法引用可保守绑定唯一方法声明，
证据为 `java_method_reference_possible_dispatch`；重载仍可歧义，构造引用保持未知，
引用不会被转换为实际 `CALL`。新增测试还覆盖模块与同名函数/类之间的伪遮蔽。

语言选择、解析分派和覆盖解释共用前端注册表。解析/派生索引版本随事实能力改变，
旧派生数据不冒充新前端事实。`selected_structure` 解释所选文件的提取状态，全局
`index_partial` 仍限制引用和路径的完整性。

增量验收发现过语言分派读取完整文件摘要而扩大重绑范围的问题，已改为独立、可追踪的
语言字段依赖。原有“新增无关声明仍复用 3 个文件关系”的断言保留并通过；语言变化和
TS 导出变化仍会让相应调用方失效。

真实 stdio 验收还发现并修复了独立 `colink live` 命令未挂接结构索引的问题：
现在首次结构查询才创建索引服务和派生数据库，文件/文本读取保持不创建数据目录；
退出关闭索引所有权，重启可继续查询保留的索引。四种结构语言均经过两次真实进程启动验证。

## 4. 搜索预算与性能

文本搜索现在按单条匹配的精确 JSON 成本增量核算，缓存可变元数据成本；固定长度
游标只在返回页面时签名。最终响应仍进行准确编码检查，读取次数、扫描字节、
来源前后验证、匹配顺序与续读语义保持不变。

严格后端对照为每场景 50 样本 × 2 个独立组，交替顺序测量；全部响应等价。
一页 200 条结果的 P95 如下：

| 文件数 | 第一组：基线 → 修改版 | 第二组：基线 → 修改版 |
| ---: | ---: | ---: |
| 1 | 12.616 → 2.154 ms | 12.843 → 2.095 ms |
| 1000 | 22.252 → 11.403 ms | 22.040 → 11.886 ms |
| 5000 | 68.263 → 56.403 ms | 74.355 → 60.677 ms |

高匹配场景的全响应编码与游标签名从每请求 201 次降到 1 次。上述计时包含本机
Live 搜索和源码验证，不含 MCP 传输、隧道、原生 UI 或模型；另行保存真实 stdio
MCP 请求计时，不能把这张后端表当成网页延迟。

限制同样保留：5000 文件高匹配 P95 改善约 17%–18%，尚未达到计划中的 20%目标；
无匹配仍需全量扫描，约 1.2 秒；1000 文件窄预算第二组 P95 11.175 → 13.412 ms，
P50 则为 10.498 → 10.447 ms，不能声称所有场景全面加速。没有新增候选文本索引，
也没有取消源码校验。RSS 记录是共同进程的生命周期高水位，不用于两版内存优劣比较。

一文件、200 匹配的真实 stdio MCP 对照也完成了两组各 50 个样本，响应逐项等价。
两组 P95 分别为 14.853 → 3.920 ms、15.022 → 4.194 ms；第一组与末期 CLI 检查有
短暂并发，原始数据保留，不将其当作安静机器或网页/模型端的延迟承诺。

## 5. 构建清单、Rust 与 CI

构建过程现在在签名前生成 `Resources/colink-build-manifest.json`。开发包标记
`workspace` 来源；自包含包在实际 backend 复制后重写为 `bundled` 来源，记录实际
Python 模块的逐文件 SHA256、整体摘要、项目/包/App 版本、解析/索引版本和能力。
它能检查内容、增删文件及版本不匹配，不能代替系统签名或安装运行验证。

清单以文本/AST 读取目标版本，不导入目标模块。只有 workspace 自身恰为 Git 根时
才记录 commit，否则明确 unknown；dirty 范围明确限定构建输入。生产后端仍为
Python，Rust 未启用。

Rust 仅复用已有 release 二进制和既存 SootUp 128 文件/193 边冻结事实，在新目录
完成 metadata/strict 各 6 项请求与 Python 参考的完整响应比较，并验证源码变化被拒绝。
本轮没有编译、调参、扩语料或测量 Rust 性能，也没有以历史性能结果为由接入生产。

CI 增加代码智能契约检查，涵盖预算、读取/搜索、日常路由、语言前端、值流、覆盖、
查询等价性和构建清单。现有平台边界保留；本轮本机结果不代表远程 GitHub Actions
或新增 Python 运行时矩阵已实际执行。
