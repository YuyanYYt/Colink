## 日常操作

1. 从应用程序或工作目录内打开 CoLink，点击菜单栏图标。打开本身不启动连接，
   不占 Dock，也没有开机自启。
2. 在连接关闭时选择工作区文件夹。候选项目按标记和有限目录信息发现；不把
   任意子目录全部授权、不在发现时建立所有项目的源码索引。
3. 「项目管理」查看/启用需要提供的项目或管理已确认的边界。新项目须本机确认，
   同名项目用路径限定名区分，旧人工名称保留。无 Git 的新 Python/Java 项目有配置
   即可发现；无标记/空目录可手动登记。网页使用唯一项目 ID，不以名称扩大权限。
4. 手动点击启动。默认只能读取；询问某项目只按需访问该项目，网页不必为了在
   已启用项目间选择而反复切换菜单栏目录。
5. 真要修改时，打开「允许修改代码」，只勾选要允许的项目。未收到后台成功确认
   前不显示已开启；网页没有替你开启开关或扩大目录范围的工具。
6. 一项功能需要分轮改 A/B/C 时，让网页保持同一写入任务；验收后完成该任务，
   需要有意恢复代码时使用用户已保存的 Git 版本；CoLink 不提供代码回退按钮/工具。
7. 关闭写入开关撤销权限但不丢弃恢复材料；「关闭」停止本次自有连接；「退出」
   停止连接并退出。重开/重启后连接和写入都须重新手动开启。

本机开关与 ChatGPT 的工具批准是两层独立控制。平台可要求确认或按当前设置记住
工具选择，不能承诺所有账号、对话都不弹窗，更不能用只读注解伪装写入。

## 网页任务的正确顺序

读取与结构查询仍使用原十五工具。代码已经完整贴在对话时，直接解释；缺上下文
且确为用户本机代码时先选择已启用项目，概览/搜索，再读必要范围。

写入只在用户明确要求和本机项目授权均成立时进行：

1. 用 `write_task_status` 取得新开始票据，以它调用 `begin_write_task`。
   大项目优先给显式 `paths`；预先声明待修改的文件、待创建的文件和必要父目录。
   声明最多 1000 个路径，不用后来的参数偷偷扩大任务。
2. 对目标做新直读，使用返回的真实完整文件 SHA256 和准确源码/物理行号。
   行号只是定位，原文和哈希才是提交保护；不能单靠缓存索引行号修改。
3. 用 `apply_edit` 进行行插入、行替换或唯一片段替换。一次工具在本机自动完成
   核验、空间预留、首次触及的起点保存、持久意图、原子提交及实际读回，
   网页不必再调用独立「备份工具」。
4. 新对象用 `create_directory` 和 `create_file`，先逐个创建已声明的父目录。
   已有对象不覆盖。原安装版没有独立删除接口；客户端升级且实际列出 `delete_file`
   后，才可在同一任务中用当前完整 SHA 删除明确要求的单个源文件。新维护源码
   不提供用户撤销；删除前请确认需要的 Git 版本。不提供递归删除、重命名、终端。
5. 每笔不同操作用新的 `request_id`；同一次重试才复用同标识与全部相同参数。
   `REQUEST_ID_CONFLICT` 只表示标识复用错误，不是源码冲突。
6. 保存后用新读取上下文确认需要的正文和 `get_diff`。旧上下文/哈希拒绝时停止
   并重新理解实际内容，不盲目重写。完成用 `finish_write_task`，不是为每轮另建任务。

`WRITE_DISABLED`、过期依据、额度不足或冲突都不是「保存成功」。待恢复状态必须由
本机受控恢复；网页不能强制覆盖外来修改或开启权限。普通答案不必展示任务/校验
标识或递增版本数字。

## 修改中间有一轮稳定，怎样保住它？

使用项目自己的 Git 保存稳定版本。仅安装 Git 或存在 `.git` 不代表当前内容已经
被记录；未跟踪的新文件、未保存/未提交的修改不能保证恢复。重要稳定点应由用户
明确选择文件并保存，CoLink 不替用户自动 commit/stash/reset/checkout/clean。

`finish_write_task` 只表示该写入任务完成，不运行测试、不提交 Git、也不创建可任意
回退的版本节点。后续任务仍有有界 Diff 起点，但这些材料不提供用户主动代码回退。

## 没有镜像，为什么仍然能 Diff？

普通读取直接读原文件，结构索引只保存有界事实，不保存完整项目正文。写任务开始
记录文件/来源校验；首次真正修改某文件之前才保存该文件起点，后续小改不覆盖起点。
`get_diff` 比较任务起点和已核验的实际最后内容，跨轮累计；它只比较，不恢复代码。
新增文件/目录记录本任务所有权；写入中断保留持久状态，只有本机可受控恢复。
兼容读取旧版已回退任务/未完成日志，不意味着重新开放主动回退；多文件提交仍不
承诺同一文件系统瞬间原子变化。

未保存起点的任意外部编辑没有历史正文，不能完整还原其 Diff。没有任务基线就
明确 `NO_TASK_BASELINE`，不能当成零差异；Git 存在时可作为另外的历史来源，但
CoLink 写入不自动 stash、提交、reset 或改变 Git 索引。

## 存储不是零，但有上限

- 单文件源码上限 4 MiB，按页返回，不把整个工作目录限制成旧镜像的总正文配额。
- 新恢复区默认常驻 64 MiB、管理峰值 128 MiB；元数据库 16 MiB、每任务 1024 操作。
  只保留最近一项完成比较基线，最多七天；活跃/冲突/未完成恢复受保护。
- 只回收协调器登记并验证且无引用的对象。空间不足先拒绝新写入，不删除未知
  文件、旧镜像、密钥或测试/构建目录。完成新任务后更早的完成点可能退休，
  不能把本机制当无限历史备份。
- 元数据清单、读取上下文、索引和监听也有独立全局预算；不复制未查询项目的全文。
  这些不是整个电脑磁盘/RAM的硬上限，真实企业规模和网页模型延迟仍须实际测量。

容量/实际 300 次小改测量见 [WRITE_IMPLEMENTATION.md](WRITE_IMPLEMENTATION.md)，
组件规模测量见 [LIVE_READ_BENCHMARK.md](LIVE_READ_BENCHMARK.md)。

## 自包含候选包与私有验收包

通用自包含新模式包由以下命令生成，不含维护者凭据和个人目录；输出目录必须全新：

```sh
uv sync --locked
uv run python macos/package.py --output-dir .artifacts/releases/colink-0.5.0b2 --source-mode live
```

打包不安装、不迁移旧库、不创建账号或 Tunnel。首次打开通用包在用户自己的应用
数据目录设置连接；首次来源仍是自带样例。Apple Silicon/macOS 14+、ad-hoc 签名，
未公证。版本变化需要重新构建发行包，不需要为每次小改打包。

`--portable-runtime` 和 `--runtime-workspace` 只用于工作目录内的私有本机验收。
这种包绑定维护者独立状态，不是公开分发物；通用包不能带这两个参数。实际验收
与候选归档分别留证，不把生成 DMG 当成系统安装/任意账号网页成功。

维护者原 0.4.3 应用已在明确更新授权后移到废纸篓可恢复，没有再复制一份应用备份；
旧持久数据、配置和固定恢复锚点保留。遇到重大问题按
[ROLLBACK_0.4.3.md](ROLLBACK_0.4.3.md) 退回，不靠删除旧数据「解决」兼容。
