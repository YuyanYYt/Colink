# CoLink 本机更新与旧版清理约定

2026-10-06 用户指令：「以后默认覆盖电脑的安装版，然后将旧应用的缓存和数据清除。」
本文件固定后续维护流程，不代表已实施自动更新器，不追溯改变此前只交付源码的事实。

## 默认更新

CoLink 自身影响应用包的源码、资源或运行时改动完成并验证后，默认构建、验证包身份/
版本/签名，再更新本机安装版；不是每次修改被连接项目的代码都重新打包。
纯文档、设计、只读诊断不强行打包。规则不授权 GitHub 发布、开机自启、扩目录、
开启写入或终端权限。重启后的授权仍遵循默认关闭和原项目范围。

更新后核对实际安装路径/版本、菜单栏启动/关闭和必要控制路径，再进行旧版清理；
源码测试不替代真实新安装版验证。涉及登记格式或数据库的迁移须先确定兼容路径，
不得通过清空数据库绕过失败。安装/迁移验证失败则保留原安装状态并报告。

## 默认清理范围

仅处理证明属于 CoLink 旧版、可以重建且新版已不引用的内容：

- 旧版专属编译缓存、失败/重复构建、临时安装验证副本和测试派生数据。
- 更新验收后不再需要的旧应用副本；不长期保留重复安装版。
- 旧版专属的可重建派生缓存；名称带旧版本不等于自动满足清理条件。

执行前通过实际路径、所有权、运行进程与引用核对精确对象，记录清单，不递归清空
宽泛工作区或缓存根。该范围已有默认授权，不因每次同类更新都再次索要“是否安装”；
用途不明、共享使用或超出该范围的对象仍需单独确认。

原始资料/源码、目录选择、连接配置、凭据、当前或复用数据库、依赖锁文件、全局
Skill 工具和未完成写入恢复记录不属于旧版垃圾，不自动删除。
`.code-context` 是持久数据，不因应用包更新就整目录清空。

优先采用可恢复清理；永久删除需用户明确授权。没有确认可安全迁移与清理时报告
限制，不为了满足“清除数据”而重置用户连接。完成后报告删除/移走的具体对象、
可恢复性和实际安装版本，不能把规则记录当作实际执行结果。

## 本次记录的边界

本条为之后维护的默认流程。本次仅保存规则，未覆盖现有应用、删除旧数据库、
清理缓存或修改目录/连接授权；此前源码维护记录和恢复锚点保持原事实。
