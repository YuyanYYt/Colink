## beta.1 本机安装后的补充验收

不是绑定私有工作目录的验收包；安装到 `/Applications/Colink.app` 后严格签名校验通过。
原 0.4.3 应用移至废纸篓可恢复，未复制额外应用备份；原凭据和 baseline profile 的
安装前后指纹一致，旧镜像数据库/固定恢复锚点未删除或迁移。

只连接工作目录内自带样例，未修改 LangGraph 或任何业务源文件。实际结果：

## 已完成的真实网页链路

| 场景 | 实际网页结果 | 独立本机核对 |
| --- | --- | --- |
| 默认关闭 | 可发现新工具；开始任务返回 `WRITE_DISABLED` | 无活动任务，样例不变，写入关闭 |
| 第一轮唯一片段替换 | `main.py` 的 `value=title` 变为 `value=title.strip()`；保存后读回和窄 patch 一致 | 实际磁盘仅这一行改变；日志只有一笔编辑 |
| 相同请求重试 | 原参数/原标识重放同一次编辑，返回相同保存结果 | 未增加操作，不重复插入或叠加 `.strip()` |
| 第二轮精准插入 | 同一任务，用 `insert_lines` 在 `MetadataClaim` 最后字段后加入 `as_dict()` | `models.py` 仅新增空行和两行方法，起点不被覆盖 |
| 第三轮目录/文件 | 同一任务创建 `colink_web_check/result.py` 和父目录，读回四行正文 | 两个修改文件、一个新文件、一个新目录；持久日志共四笔源修改 |
| 完成任务 | `finish_write_task` 返回 completed，保留最近整体恢复点 | 一项任务，四个成员和一笔完成记录；没有分成三个任务 |
| 请求标识冲突 | 不同操作误用既存标识返回 `REQUEST_ID_CONFLICT`，未进入源文件回退 | 操作数量、三个任务文件正文和 completed 状态不变 |
| 外来文件回退保护 | 新独立请求真正返回 `WRITE_ROLLBACK_CONFLICT: target set changed; no source changes made` | 三个文件仍与任务最后哈希一致，无部分恢复；任务仍 completed |
| 整项回退 | 一次 `rollback_write_task` 返回 rolled_back；新直读确认原文件恢复、新对象不存在，原 `get_diff` 为零 | `git diff --exit-code -- examples/sample_project` 成功；新增目录不存在；六笔持久操作中的最后一笔是已完成 rollback |
| 旧哈希写入保护 | 独立第二项任务第一次保存成功；另一新标识携旧 SHA256 返回 `WRITE_HASH_CONFLICT` | 仅一笔编辑；没有再次修改、完成任务或网页回退 |
| 菜单栏整项回退 | 原生按钮确认范围，待后台应答；任务随后 rolled_back | 原文件恢复到 Git 起点，活动任务清空；新增一笔本机回退记录 |
| 菜单栏撤销写入 | 开关关闭并等待后台；网页新开始请求返回 `WRITE_DISABLED` | 写入授权清空、无活动任务；新直读原内容、原 Diff 为零 |

外来冲突用一个维护者创建、任务未登记的 `external.txt` 验证目录保护，不改任务文件的
已保存状态。负向验收后将该文件移动至独立验收目录保留，没有删除它或修改恢复记录来
绕过检查，然后才进行正常整体回退。这证明外来目录项保护，不冒充任意并发/断电测试。

原生回退验收发现回退终态误显示为「任务待确认」；后台和按钮禁用逻辑正确。
已将 `rolled_back` 的界面文案补为「任务已回退」；上方安装版补充已实际确认该显示。

## Diff 和空间的实际边界

这条链路使用实时原文件和任务起点，不创建整库源码镜像。三轮中途的原 `get_diff`
正确汇总累计修改，整轮回退后才报告零；外部变化不能被重新读取悄悄采纳为任务基线。
没有事前内容/Git 基线的任意外部修改仍不可还原历史，不能将 `NO_TASK_BASELINE` 说成零。

第一次任务回退后，实际恢复区常驻分配 **204800 字节**、数据库页 **135168 字节**、
五个正文对象的分配 **20480 字节**，正文原始合计 **1090 字节**，没有 SQLite 辅助文件。
五个对象是两个原文件起点和本次回退需要的最新内容，不是五份完整项目或逐轮镜像。
其他分配包含已登记的任务/请求/属性/路径及文件系统页开销；不是编译缓存。
这只是微型真实网页样例的观测值，不是任意项目固定占用。默认全局恢复预算仍为
64 MiB 常驻/128 MiB 管理峰值，1024 操作/任务、最近一项完成点/七天，活跃及待恢复材料
受保护。300 次/100 KiB 的独立本地测量见 [WRITE_IMPLEMENTATION.md](WRITE_IMPLEMENTATION.md)。

第二项任务回退后，只保留这项最近恢复点，前项完成/回退点按已实现策略退休：
常驻 **126976 字节**、数据库页 **118784 字节**、两份正文对象分配 **8192 字节**，
辅助文件为零。这是实际跨任务有界保留现象，不是维护者手动清数据库或删除生成物。

现有已安装 `colink-code-context` 的名称/身份和图标保留，正文和描述在网页编辑器更新，
`agents/openai.yaml` 的 `allow_implicit_invocation: true` 已实际核对。不是新增同名副本。
网页真实使用暴露不同操作复用请求标识的问题，规则已收紧：每笔新操作新标识，只有
同一次相同参数重试才复用；请求标识拒绝不等于源码冲突或回退预检已经运行。
此阶段的写入对话从显式选择 CoLink 开始，不算新的隐式 Skill 匹配证据。

不能推断新账号/新对话/其他权限策略也不会确认，更不能把本机开关当成平台确认替代。
