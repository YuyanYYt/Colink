# CoLink 三档模式与数据库配置完整实施计划

日期：2026-10-07（Asia/Shanghai）。状态：计划报告，尚未实施。

本报告以用户最后确认的范围为准：主面板上半部分保持现版形状；发现候选继续放在项目管理内；只调整只读、写入、开发三档入口及数据库配置入口、配置窗口和必要的数据库连接层。现版写入、运行、项目开关和撤权逻辑作为实施基线。

**1. 本轮目标与范围**

完成两件事：用三个简单的模式按钮组合现有写入与运行能力；让数据库配置页面能够读取真实项目配置、复用已有数据库连接，并清楚显示测试结果。

| 范围 | 本轮处理 |
| --- | --- |
| 主面板上半部分 | 图标、连接状态、文件夹卡片、路径、选择文件夹和项目管理的位置、形状保持现版。 |
| 项目发现与项目管理 | 发现候选仍在项目管理内；沿用当前项目登记、开关和父子目录边界。 |
| 权限操作入口 | 原有两个开关替换为只读 / 写入 / 开发三个按钮，底层继续调用现有控制接口。 |
| 数据库入口 | 开发环境与数据库引导改名为数据库配置。 |
| 数据库配置窗口 | 保留项目选择，增加项目配置 / 手动配置两种来源，缩短表单和提示。 |
| 数据库连接层 | 实现静态配置解析、已有库名和账号兼容、真实认证测试及安全的短错误提示。 |
| 环境信息 | 复用现有识别结果，改成默认折叠；本轮不另建环境导入系统。 |
| 执行架构 | 保留 Python 协调器、现有进程管理和原生沙盒；Rust 留到独立下一阶段。 |

原讨论中的按项目分别设置模式、重做工作目录继承权限、只撤销单个项目作业等方案不进入本轮。当前项目开关触发全局写入/运行撤权的行为保留。

**3. 保留现版操控逻辑**

网页链路保持为：ChatGPT 网页 → 现有远程 MCP → CoLink 现有协调器 → 受控文件操作或沙盒作业 → 状态与增量输出。

- 项目管理开关决定某个 project_id 是否允许被访问。已登记子项目继续从父目录范围排除，关闭子项目后不能通过父目录入口读取。
- 写入继续绑定本机确认的 project_id 和源目录身份；修改仍通过现有写入任务、哈希检查及恢复记录。
- 运行继续要求本机执行授权、原生保护、明确项目、端口和网络范围，沿用当前作业账本、输出、截止时间和取消监督。
- 现版关闭写入会同时撤销运行；关闭运行不因此撤销既有写入；发现候选、登记和切换项目开关仍沿用现版撤权行为。
- 项目管理的可操作条件、恢复中的限制、连接断开和重启默认关闭授权的行为保持现版。

本轮没有新的永久权限总开关，也不因为模式按钮显示开发就自动授权大目录下的所有项目。模式是操作入口；实际可读、可写、可运行的项目仍以现版授权结果为准。

**4. 三档模式的具体实现**

| 模式 | 成功后的实际状态 | 调用现有流程 |
| --- | --- | --- |
| 只读 | 写入关闭，运行关闭；已允许项目仍可读取。 | 复用 disable_write 的现版撤权流程。 |
| 写入 | 已选范围写入开启，运行关闭。 | 必要时先 disable_execution，再走现有写入项目选择与 enable_write。 |
| 开发 | 已选范围写入与运行均开启。 | 依次复用写入授权、运行授权和现有端口选择；已有效的授权按现版校验复用。 |

按钮只显示只读、写入、开发。正常状态下不再附带工具数量、长段解释或括号版名。现有任务状态、必要的恢复入口和短错误反馈保留。

授权窗口继续使用现版项目选择、端口和确认流程。未选项目、取消授权、沙盒未通过、恢复未完成或服务端没有准确确认授权范围时，不能把目标模式显示为已经生效。

三档切换按现有控制调用顺序执行。选择开发后，如果写入已成功而运行授权被取消，显示实际的写入状态；不得显示开发，也不自动扩大已选范围。存在停止中的作业时，保留简短的正在停止状态，不把撤销执行授权当成已经核查进程退出。

现版可以单独允许执行而不允许写入。新版三档入口不主动产生这种组合；如果遇到旧会话或异常恢复中的只运行状态，保留实际权限并暂不选中不符合事实的模式，显示授权状态需确认，由用户选择三档之一。不得静默补上写入权限。

界面只是组合入口，不新增后端权限状态机或更换 WriteCoordinator、ExecutionCoordinator、ProcessManager。

**5. 数据库配置窗口与产品文案**

原按钮改为数据库配置，窗口标题也为数据库配置。沿用现有窗口样式和项目下拉框，减少默认展开内容。

下面为布局示意；地址、库名、用户名及文件名均按实际解析结果显示，不把示例当成已发现的真实项目配置。

```text
数据库配置

项目        [ backend · NailGlow/backend ▾ ]
连接来源    [ 项目配置 ] [ 手动配置 ]

类型        MySQL
地址        localhost:3306
数据库      nailglow
用户名      root
配置来源    application.yml
状态        未测试

            [ 重新读取 ] [ 测试连接 ]

▸ 高级设置

```

项目选择仅选择要查看或配置哪个连接，不更换主工作目录、不重建 MCP 连接，也不更改项目授权。列表仅包含当前已允许且可用的项目。

项目配置模式默认展示类型、地址、库名、用户名、来源和状态，凭据明文不展示。手动配置展开类型、地址、端口、库名、用户名和密码，主操作为保存并测试。重新打开时恢复该项目已保存的手动连接，不用每次重新填写。

开发环境默认折叠，展开后复用现有工具识别结果。界面不宣称检测到工具就代表项目已经可运行，也不自动安装工具或重复创建虚拟环境。TLS 等选项放在高级设置，沿用现版安全策略。

删除三段长教学、强制专用账号的说明、colink_ 占位要求以及满页工具版本列表。必要字段可以通过短提示解释，例如用户名指数据库账号。

**6. 自动读取项目配置**

增加一个本机静态解析组件，数据库目标的优先来源为用户选择的当前项目配置，而非 CoLink 曾经是否创建或绑定过这个项目。

首版覆盖以下静态配置：

| 配置形式 | 读取内容 |
| --- | --- |
| .env、明确的项目环境文件 | DATABASE_URL、SQLALCHEMY_DATABASE_URL、DB_HOST / DB_PORT / DB_NAME / DB_USER / DB_PASSWORD 等连接字段。 |
| application.yml / application.yaml 及明确的 Spring profile 文件 | spring.datasource.url、username、password，及可静态解析的项目变量引用。 |
| application.properties | 同等数据源字段和项目变量引用。 |
| compose.yaml / docker-compose.yml | 可明确映射到本机端口的数据库服务、库名与账号；多个候选需要用户选择。 |
| Prisma schema | provider 与环境变量名；实际连接值从已选项目的环境配置取得。 |

只扫描当前允许的项目范围内常见配置位置，保持目录身份、子项目排除、链接和文件容量检查。选择大目录容器时遇到多个子项目或数据库候选，应显示候选选择，不跨越关闭项目扫描，也不替用户选生产配置。

不运行配置脚本，不导入项目代码，不执行 .env 中的 shell 内容，不执行 YAML 标签。不能静态确定的动态配置，明确提示改用手动配置。YAML 解析采用显式锁定的安全解析依赖，更新 uv.lock，不依赖未声明的传递依赖。

项目中的 .env 继续不经普通文件读取工具返回网页。解析器只在本机取得连接字段，返回脱敏后的来源和目标。变量只从明确的项目环境来源或用户为此连接提供的值解析，不继承主控服务的任意环境或凭据。

发现缺失变量、多个 profile、多个数据库、同级环境文件冲突时，显示缺失项或候选；不执行配置、不猜 root、不猜库名。

重新读取、测试和执行前检查配置来源和目标是否变化。变化后旧连接证明及相关计划失效，重新取得有效连接或计划。切换项目时取消或丢弃旧请求结果，防止连接、状态或密码串到另一个项目。

**7. 复用已有数据库与账号**

同一个 MySQL 3306 实例可有多个数据库，CoLink 按当前项目配置选择对应库。现有实例不因接入 CoLink 而复制或重建；已有服务仍使用实际端口。PostgreSQL 与 pgvector 同理，检测 pgvector 扩展不等于另建实例。

移除仅允许 colink_ 前缀的业务约束，接受普通现有库名；保留安全的输入验证、明确参数和目标检查。允许项目已有的 root 或 postgres 账号，不强制创建新账号、修改密码、迁移数据或新建库。

用户名和库名缺失时显示缺失项，不自动默认 root。密码按已读取配置或手动输入取得；需要无密码方式时必须能准确表达这一方式，不能把缺失凭据误当成已经配置成功。

用户已经确认接受沿用已有账号并按项目目标操作。root 的真实数据库权限不会因选择项目而自动收窄；计划、界面和 MCP 结果均不把 root 描述成数据库强隔离账号。

继续保留本机回环地址边界、TLS 策略、受控命令和现版沙盒。支持已有 root 不等于关闭原生保护或允许任意网络目标。Qdrant 的现有配置记录兼容保留，其执行支持不足继续明确标注。

**8. 真实连接测试、保存与错误反馈**

测试执行固定的只读认证和目标检查，确认服务可连接、客户端登录成功及目标库可使用。手动保存只在参数和实际认证通过后替换当前连接。测试失败保留旧的有效连接，不污染用户项目文件或旧凭据。

| 可见状态 | 含义 |
| --- | --- |
| 未找到配置 | 未取得可用项目连接，用户可选配置文件或手动配置。 |
| 未测试 | 取得连接目标，但尚无本次真实认证结果。 |
| 测试中 | 正在执行有截止时间的固定连接测试。 |
| 已连接 | 当前目标完成认证与目标检查；仅代表这次连接测试成功。 |
| 连接失败 | 显示具体且脱敏的短错误，不保留错误的成功状态。 |

端口可连接不能单独显示已连接。单次连接成功也不能显示迁移、CRUD、密码强制检查、有限角色证明或应用可用均已完成。

| 错误分类 | 示例提示 |
| --- | --- |
| 服务或地址不可达 | 无法连接，请检查地址和端口。 |
| 用户认证失败 | 请检查用户名和密码。 |
| 库不存在 | 数据库不存在，请检查库名。 |
| 权限不足 | 当前账号无权访问此数据库。 |
| 配置变量缺失 | 缺少 DB_PASSWORD，请补充配置。 |
| 缺客户端 | 未找到 MySQL 客户端。 |
| TLS 验证失败 | 连接验证失败，请检查高级设置。 |
| 请求或配置已变化 | 配置已变化，请重新读取。 |

提示由固定错误分类生成，不直接把数据库客户端 stderr、连接 URL 或密码回显到界面或网页。操作具有超时、输出容量与项目身份检查，不等待交互式密码输入。

测试临时凭据采用有归属的本机生命周期，失败不留下孤立钥匙串项。旧凭据在新连接确认成功前保留。自动来源使用本机读取的凭据；手动来源继续使用当前钥匙串机制。

连接测试不创建/删除库、账号或表，也不修改业务数据。数据库开发操作继续通过现有授权作业执行。

**9. 网页使用链路与安全边界**

保持现有 execution_environment、database_status、execution_plan、execution_start、execution_status、execution_output、execution_cancel 等工具的用途和显式 project_id。

网页先取得环境、数据库目标与连接状态，再由现有计划和沙盒执行器运行项目命令。数据库密码、原始含密配置和完整连接 URL 不返回网页；运行输出继续做凭据脱敏。

仅为数据库解析、连接状态和安全错误增加必要字段；保留旧字段的兼容语义，不新建一套通用数据库管理 MCP 或后台模型循环。配置页面不会成为 SQL 编辑器。

数据库目标、配置或凭据变化后旧计划不能继续操作旧目标。保留现版作业幂等、输出游标、取消和重启中断语义，不修改执行账本和写入恢复记录的格式。

普通开发指令沿用现版授权流程。删库、清空整表等危险操作必须有明确目标和具体操作意图；本轮不以测试或初始化为由执行这些动作。ChatGPT 是否展示指定确认界面由客户端决定，MCP 注解不当成服务端可验证的人类批准凭据。

**10. 持久化与回退兼容设计**

保留现有手动 profiles.json 与钥匙串引用，旧连接继续能读取。自动来源选择、候选配置和来源身份存放在独立、私有、容量有界的来源元数据中，不把明文密码写进去。

自动解析结果按实际源配置形成临时连接；来源记录只记录已选择的配置、项目身份和必要的验证信息，项目配置仍是目标的权威来源。

连接成功记录与有限角色证明分开。允许 root 后不能把旧 role_check=passed 重新解释成只要连得上；新连接证明单独记录认证、目标、时间、输入指纹和实际账号范围，不伪造旧隔离证明。

优先使用兼容 sidecar 增加来源和连接证明，不改变现有写入恢复、执行账本与旧快照结构。新版本读取没有 sidecar 的旧数据时按原手动模式工作。

旧版软件回退时恢复旧手动连接数据，新自动来源元数据保留但不要求旧版识别。回退到 0.5.0b4 也意味着回到它原有的账号限制和功能，不能承诺旧版继续具备新版自动读取能力。

损坏、来源目录替换、未完成写入恢复或不兼容迁移均应停在可解释的状态，不删除数据修复，不静默授予权限。

**12. 实施顺序**

1. 冻结 0.5.0b4/build 10 基线：核对当前源码、安装包、版本、签名和配置；保存源码恢复锚点与现有未提交工作，列出配置备份范围。
2. 实现三档模式适配：组合现有写入/运行调用，保留项目范围、授权窗口、取消和失败行为；用实际界面验证授权成功、取消和状态反馈。
