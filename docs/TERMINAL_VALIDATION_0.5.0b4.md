# CoLink 0.5.0b4 本机、网页与安装验收记录

记录日期：2026-10-07。安装版本为 **0.5.0b4 / build 10**，路径为
`/Applications/Colink.app`。本文保留实施结果；用户明确要求清理后，独立测试项目、
人工数据库、测试依赖和旧应用副本移入废纸篓，不再作为当前运行环境。
本文不代表 GitHub 发布，也不把人工向量或一次本机计时作为业务性能保证。

## 实现及判断边界

- 采用 Python `ExecutionCoordinator`、原生 macOS 隔离、固定 SRT 0.0.78 和
  Codex 固定提交 `d27764b82f7118f674371e6d6e76271d9d606edb` 的机制借鉴；
  没有同时捆绑完整 Codex 后端，也没有引入 Rust 构建链。
- 网页调用与作业生命周期分离，提供规划、预演、幂等启动、状态、游标输出、取消、
  项目作业找回，以及环境、端口、数据库状态、受控移动和本地 Git。
- 原文件修改继续通过 WriteCoordinator。终端与写入权限分别由本机明确开启，
  断开、退出、来源切换或重启撤销授权；网页不自行开启权限。
- 网页修复预算绑定服务端签发的开发任务 ID。跨新 ID 的同一自然语言目标无法自动
  合并计数，因此不能承诺整个自然语言目标只能执行五轮。
- 当前为非交互管道。PTY、终端输入和尺寸调整未实现。Python/Java 开发服务需使用
  Unix socket，Node/Vite 使用适配器；通用 Spring/Tomcat TCP 服务尚未适配。
- MySQL/PostgreSQL/pgvector 已有下述真实证明；Qdrant 仅连接配置，尚未向项目执行
  交付密钥。首版不自动安装数据库或重启用户的既有数据库，提供中文配置引导。
- CPU、内存与进程数量为采样监督和停止阈值，属于软限制。Seatbelt 与原生资源组
  不构成虚拟机级资源隔离。

## 实际 ChatGPT 网页闭环

入口为用户 Chrome 中原有「MCP能力对比」会话。通过 computer use 在实际输入框发起
开发请求，网页模型调用 CoLink 工具。原始项目仅为
`examples/sample_project/terminal-web-20261007`，
`project_id=p_302ff4b1f7995ca4fb92eaa29c98d992`。
前端使用 43117、后端使用 43118；人工 PostgreSQL 使用 43122。
没有修改既有 `supermarket-system`，没有连接、修改或重启既有 3306/5432 数据库。

1. 工具发现与环境/端口/数据库检查成功。网页受控创建前后端、页面、迁移、Python
   requirements 和中文引导，保存后实际读回并完成写任务。错误文本片段被严格拒绝，
   重新读取后继续，没有关闭原文件检查。
2. 网页创建私有 venv、安装 `six==1.17.0`、实际 import 输出版本，完成 npm 安装
   与 PostgreSQL/pgvector 迁移。预演与启动复用同一执行结果，没有重复安装。
3. 后端故意保留错误，网页读取 `exit 1` 和 `COLINK_WEB_INTENTIONAL_FAILURE`，
   受控删除错误行、读回、新建计划并重新启动。用户意外退出候选应用后，重连找回
   原六项作业 ID 和退出/清理结果，没有自动重跑旧作业。
4. 前后端同时运行，进程、注册端口与 HTTP 健康分别确认；重复启动后端返回同一
   作业 ID。实际 Chrome 页面创建并读取记录，写入三条向量并完成近邻查询。
5. 实际刷新 ChatGPT 页面后找回同一组服务作业。只取消旧后端，确认退出、清理和
   43118 释放；前端保持原 ID，后端重新启动后实际页面读到原数据。
6. 网页创建验收说明、受控移动到 `notes/acceptance-note.md`、读取移动结果，再
   只提交该文件。提交重试返回同一提交；独立 Git 查询确认原 requirements 暂存
   内容及 blob 不变。有限 SQL 作业完成插入、更新、读取和删除人工临时记录。
7. 人工 PostgreSQL 精确正常停止并重启同一数据目录。实际浏览器再次点击读取记录
   与向量，数据仍一致。最终因用户要求清理而停止人工数据库与服务。
