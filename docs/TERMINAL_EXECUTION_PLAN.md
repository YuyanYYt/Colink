# CoLink · 本机执行、依赖安装与 dry run 方案

日期：2026-10-07（Asia/Shanghai）。状态：**提案，尚未实现、安装或开启**。
当前软件保持 0.5.0b2；首选恢复基线见 [恢复说明](RECOVERY_0.5.0b2.md)。
本文件不授权执行终端命令、安装依赖、开启网络、使用 Git 凭据或修改其他项目。

## 1. 用户目标与方案调整

网页 AI 在已授权项目写代码 → 自动准备项目依赖 → 运行/构建/测试 → 读取真实终端
返回 → 在同一权限范围内修复并重试 → 完成阶段后提交 Git；推送远程另有边界。
第一批执行适配器按本次需求优先 npm/Node 与 Maven/Java，Python 后续复用机制。
已有读取、Python/Java 关系查询与受控写入不因此更改。

Linux VM 能完成下载和运行，但原[离线 VM 首版](TERMINAL_SANDBOX_DESIGN.md)不满足
上述完整目标；VM 不是必须条件，也不能直接宣称它不可能。Linux/macOS 的平台依赖、
原生库、路径与工具链差异需要验证；优先调查原生 macOS 受限执行，VM 保留为备选。

推荐组成是**预执行计划 + 操作系统隔离 + 请求幂等 + 异步任务 + 独立 Git 代理**，
不是网页直接控制 Terminal.app、用户 Shell 或任意 host exec。
本轮仅固定需求与放行门槛，不能因文件存在就声称终端已可用。

## 2. dry run、幂等与安全不是同一个概念

| 机制 | 解决的问题 | 不保证什么 |
| --- | --- | --- |
| 预执行计划 / dry run | 展示目标项目、操作、预计影响范围、依赖、网络与额度 | 不实际跑业务就不能知道运行是否成功，也不保证任意脚本无副作用 |
| 请求幂等 | 同一逻辑请求因掉线/重试只返回原任务或结果 | 不等于无害、不等于永不删除，也不保证任意外部副作用恰好一次 |
| OS 级隔离 | 限制整个进程树的读写、网络、IPC 等实际能力 | 不是零漏洞保证；不自动理解“哪个源文件重要” |
| 权限与路径保护 | 操作只作用于本机明确选择的项目/产物/仓库 | cwd、命令白名单与模型自审不能单独提供隔离 |

幂等指相同请求多次的预期效果与一次相同；删掉重要文件也可以是幂等的，所以
不能用它替代文件保护。依据：[RFC 9110 §9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)。

具体工具并不都有相同预执行能力：

- npm 的 `--dry-run` 用于支持它的安装/更新等命令，报告拟做操作；不是任意 npm
  子命令通用保证。预览不证明安装脚本、编译或业务测试成功。
  [npm ci 文档](https://docs.npmjs.com/cli/v11/commands/npm-ci/)
- Maven CLI 没有可覆盖任意插件的统一 dry-run 开关；某个插件的 `-DdryRun` 只按
  该插件语义使用。`dependency:go-offline` 是真实依赖解析/下载，不能冒充只读预览。
  `mvn install` 还会执行前序构建阶段并将当前产物放入本地 Maven 仓库，不只是下载。
  [CLI 选项](https://maven.apache.org/ref/3.9.15/maven-embedder/cli.html)、
  [构建生命周期](https://maven.apache.org/guides/introduction/introduction-to-the-lifecycle.html)、
  [go-offline](https://maven.apache.org/plugins/maven-dependency-plugin/go-offline-mojo.html)
- Git 的 `commit --dry-run` 可看提交范围；`push --dry-run` 不更新远程 refs，
  不等于零网络或真实推送必成功。预览自身也走受控代理，不执行不可信 Git hook。
  [commit](https://git-scm.com/docs/git-commit)、[push](https://git-scm.com/docs/git-push)

优先提供 CoLink 自己的结构化 `execution_plan`：解析被允许的目标与策略，不在
主机 Shell 中“试一下”。如需调用包管理器的真实 dry-run/解析命令，该命令本身
也必须进入相同隔离，不能把它当成执行前的免检步骤。

## 3. 无 VM 的原生隔离候选与必须验证的边界

可评估 [Anthropic Sandbox Runtime](https://github.com/anthropics/sandbox-runtime)：
公开实现用 macOS Seatbelt/sandbox-exec 与受控网络代理，对进程树施加约束，
不要求容器。它仍标注 Beta Research Preview，不能直接等同成熟 CoLink 功能。

**不能原样套默认配置。** 该项目默认读取范围很宽；必须明确收紧到选中项目、
所需可信工具链和独立缓存，并排除其他项目、用户资料、凭据及 CoLink 控制数据。
不允许工具层指定额外根目录、socket、代理、忽略规则或弱隔离开关。

候选库的域名过滤也不是完整防泄露：允许一个域名不代表只允许某个包或某个
GitHub 仓库。私网解析、重定向、父代理、Unix socket、网络直连、DNS 和 macOS
本机端口能力须单独测试。运行阶段默认不联网；依赖准备阶段仅有限包源，Git 推送
不借用依赖阶段放行 github.com。库作者的安全限制不能被包装后隐去。

实施前锁定候选版本/源码摘要、审查许可证和已知限制，在支持的 macOS 上完成
兼容与攻击矩阵。新系统不支持、规则编译/监控失败或撤权失效时拒绝执行，
**不自动退回不受限的 subprocess**。无需 VM 是候选路线，尚不是可用性承诺。

原生沙盒与 VM 共用主机内核，强度和剩余风险不相同。不通过验证则调整方案或
缩小支持范围；不以“只有 npm/mvn”或“AI 先检查命令”代替系统限制。

## 4. 权限、读写与网络

### 本机开关：独立于写入

- 新增“允许项目运行”，默认关闭，绑定当前连接、来源、准确项目 ID 与执行配置。
- 首次可批准一段工作流：该项目的依赖准备、指定测试/构建和有界重试；不要求
  每条相同范围命令再弹一次本机框。网页客户端自己的确认机制仍由客户端控制。
- 关闭、切项目、退出、控制通道失效和重启撤销许可并取消整棵任务进程树。
- 不包含 sudo、全局包安装、修改系统配置、SSH、任意 Shell、Docker socket、
  访问其它项目或生产环境；工具链缺失的安装/升级需另行明确批准。
- 代码写入仍由原 WriteCoordinator 执行。执行许可不能代替写许可或扩权。

### 源码与产物

原生执行候选优先读取准确项目的当前原文件，不重新建立整个工作区源码镜像。
记录本轮输入清单/内容摘要；检测到并行源码变化时该运行结果标为过期，提交前
重验，不把混合状态/旧测试结果当成当前项目已经通过。

执行进程默认只读源文件；仅允许写已声明的依赖/构建/临时目录，如应用确认管理
的 `node_modules`、`target` 和该项目独立缓存。`.git`、凭据、项目根、源码/配置、
CoLink 数据/控制接口及未选中项目拒绝写；不能给整个根目录 allowWrite。
新脚手架、代码生成或锁文件调整形成变更提案，经现有受控写入核验后应用，
不为兼容生成器而放开整仓任意修改/删除。

路径必须处理 symlink/hardlink、父目录替换、Git worktree 的外部 gitdir、嵌套项目
和不同来源。目录名叫 node_modules/target 不等于一定可删；首轮核对原内容/所有权，
不能误删用户手写或符号链接指向的资料。

依赖阶段用独立网络配置和最小输入。优先可信下载代理按锁定坐标/完整性准备
缓存；需要包管理器解析时只在专用受限环境操作。不得同时给不可信安装脚本
“可读全项目＋任意联网＋用户凭据”。需要私有源/认证/新增包源时停下提出范围，
不自动复制用户 ~/.npmrc、~/.m2/settings.xml、GitHub/SSH/云凭据或继承主机 Shell。

## 5. npm / Maven 的准确行为

### npm / Node

有匹配锁文件时优先项目级 `npm ci`；它不会更改锁文件，但会删除既有 node_modules
再重建，因此只能在已批准、检查所有权的依赖目录使用。不是“命令安全所以随便跑”。
无锁/需新增依赖时，先提出 package.json 与锁文件变更，再走写入流程与受限安装。

默认不运行安装生命周期脚本；确需原生模块/安装脚本时记录包与版本，在同一
隔离环境批准该范围。`--ignore-scripts` 不是测试隔离：明确运行 `npm test` /
`npm run` 仍会执行目标脚本。精确行为按最终选用 npm 版本验证，不能套当前网页
文档的新脚本策略到用户现有旧工具。

执行适配器仅接受登记的 `test`/`build`/有界运行目标，项目脚本按不可信代码处理；
禁止网页借参数指定任意程序、配置根、全局 prefix、用户 HOME、远程脚本或 npx 下载。

### Maven / Java

固定可信 Maven/JDK 及其版本，单独项目本地仓库，不写用户全局 ~/.m2。
优先 `test`/`verify` 等适配目标；依赖准备和安装本项目产物分别记录。
插件、扩展、测试、annotation processor、项目 wrapper 都是代码，必须在隔离内
运行，不把 `dependency:go-offline` 当成安全的主机只读解析器。

验证 Maven/JVM 代理配置，不能只设置 HTTPS_PROXY 就假设 JVM 会遵守；候选库的
Java 代理适配、工具链版本、原生库与离线缺依赖反例必须实测。不足就返回明确
缺失依赖/配置限制，不以开放任意网络、复用用户密钥或禁用 TLS 验证来修好。

## 6. 执行与自动修复：异步、可停止、有界

```text
用户首次本机批准项目与配置
  → 网页 execution_plan（项目/动作/输入摘要/依赖/额度）
  → execution_start（核验 plan；快速返回 job_id）
  → 依赖准备 / 执行
  → execution_status + execution_output（退出码、增量 stdout/stderr）
  → AI 判读失败并用已有写工具修复
  → 新计划/新运行，直至验证通过或达到额度
  → 独立 git_plan / git_commit；推送另授权
```

提案接口：`execution_plan/start/status/output/cancel`，同一项目任务最多一项运行。
日志分页/游标，不能把长 npm/Maven 构建塞进一次阻塞工具调用，不能承诺 ChatGPT
网页提供完整交互式终端或每个平台都会连续自动轮询。

返回真实退出码、超时/取消/沙盒拒绝、输出截断、环境与输入摘要。stdout 中的
“全部通过”不替代进程状态，也不是让 AI 增权/执行命令的可信指令。
取消必须确认所有后代停止；无法确认则标为异常并禁止后续任务，不仅关闭日志面板。

首次提案重试预算为 5 次运行或任务 20 分钟，单命令默认 5 分钟；长任务的扩大
由本机决定。依赖缺失、权限拒绝、生产服务缺失和业务代码错误分别返回。
到预算/反复同错/需要新凭据、目录、端口时停止说明，不无限自修或自动扩大权限。

长驻开发服务/网页预览放在后续阶段，独立登记端口与停止生命周期；只绑定回环，
不开放 LAN、公网入站或其它本机服务。候选库本机端口授权可能比单端口更宽，
必须验证或提供窄代理后才启用，不能直接放开 allowLocalBinding 当成精确端口许可。

## 7. 预览与真实执行之间的冲突、幂等与异常恢复

计划绑定项目/来源/连接、操作、输入哈希、锁文件、工具链、权限配置、Git HEAD
与候选远程/分支；短有效期。开始/提交前重新检查，变化则计划失效，不照旧执行。
网页只选择允许的 profile 与结构化参数，不传任意 shell 字符串；若候选库内部需要
shell 包装，由可信适配器正确编码 argv，验证注入和整个子进程树仍受限。

`request_id + payload_digest` 持久记录：相同 ID/相同内容返回原 job；同 ID 改内容
拒绝；丢失回执先查原 job。用户明确的新测试轮使用新请求，不把“同一命令”永久
去重。并发、重启与撤权均检查身份；任务过期报告过期，不静默重跑。

沙盒异常中断后可能已产生部分依赖/产物，必须核对任务记录与实际状态，不以新
请求盲重试。没有跨任意脚本/网络副作用的 exactly-once 承诺；结果不明时暂停。
持久回执不是用户代码历史库，不能恢复已经对外执行的操作。

## 8. Git 提交与远程推送：独立窄代理

不把 GitHub token/SSH key/agent socket 交给 npm、Maven或项目进程。
运行器不能写 .git；Git 由最小权限代理处理，不提供任意 git 子命令。

- `git_plan` 展示准确仓库、分支、这项任务的文件与差异、测试所依据摘要。
- 只有明确的文件内容/哈希进入提交；不 `git add .`，不吞掉已有 staged/未提交用户
  工作、不提交 .env、缓存、日志、数据库或下载依赖。
- 比较旧 HEAD、项目身份、索引/内容，出现用户并行修改即冲突。用受控对象/临时
  索引路径实现，只允许当前任务文件；禁用不可信 hooks、内容过滤器、编辑器、
  external diff、仓库配置引出的任意 helper 等执行入口，不能拿用户原 Shell 配置。
- 提交默认到本机已批准功能分支；不 amend、rebase、reset、clean、强推、删分支
  或自动合 main。仓库不存在时创建/远程创建分别需要明确目标授权。
- `git_commit` 与 `git_push` 分开。可以首次批准“本项目任务提交”，无需每次再弹；
  推送必须明确远程仓库/分支/凭据范围，防止同域名任意仓库发布。
- 提交绑定 request_id、父提交和 tree 摘要；回执丢失查提交/引用，不再创建一份。
  推送结果不明时查远程 ref，不自动 force 或重复制造发布。

用户只说“提交仓库”时先实现本地 commit，不把它等同 push 或公开代码。
现有 CoLink 软件锚点不是用户项目备份，也不替代这一 Git 路径。

## 9. 存储与资源：避免再次堆积

不恢复完整镜像、不按每次对话保存整仓历史。应用管理的内容分为依赖缓存、工作
产物、日志与小体积任务回执，均带来源/所有权记录和保留策略。

提案默认：日志 8 MiB/任务、64 MiB 全局；完成任务最多 16 项/24 小时；运行并发 1；
独立依赖缓存 2 GiB/项目、4 GiB 全局。大项目不足时本机明确调整，网页不能扩额。
源项目既有 node_modules/target 属于用户数据时不纳入可自动销毁范围。

执行前预留和执行中监测不能声称是硬磁盘/内存配额；原生工具链的硬约束方案需
在可行性阶段验证，软监控必须明确超调风险。额度/存储保护达不到门槛时缩小支持
或拒绝运行，不无限放宽。总量统计包含应用所有可写缓存/下载/临时目录，不能仅数日志。

启用时说明并批准 managed job/缓存生命周期；仅回收已确认应用拥有、已结束且
未被运行任务使用的对象，使用有界 LRU。当前项目依赖、源码、锁文件、Git、凭据、
运行数据库、软件锚点和未完成写入记录不因过期自动删除。
本次没有实施任何新自动清理策略，也没有为此创建清理脚本。

## 调研证据边界

官方命令文档与候选库仓库已阅读；本轮没有下载/安装候选库，也没有实跑 npm/Maven
沙盒、开展攻击矩阵、改变 ChatGPT 配置或开启终端。候选库与文档会变化，实施前
重新核验接口、固定版本和运行证据。可行性原型是下一步，不以调研当成实现通过。
