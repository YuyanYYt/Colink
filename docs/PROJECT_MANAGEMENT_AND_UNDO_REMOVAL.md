# CoLink · 项目识别修复与移除代码回退

日期：2026-10-06；源码版本 0.5.0b2。范围：不覆盖本机安装版、不发布 GitHub/安装包、不修改
真实 NailGlow 项目或扩大授权。终端能力只记录设计，见
[TERMINAL_SANDBOX_DESIGN.md](TERMINAL_SANDBOX_DESIGN.md)。

## 项目发现与名称

- `.git` 不是必需条件：`pyproject.toml`、`pom.xml`、Gradle 配置也可作为项目证据。
- 已登记但自身不带这些标记的工作区根是容器，之后新增的 Python/Java 项目可以被
  单独发现；带标记的实际项目与明确登记的非根项目仍保持子模块边界。
- 空文件夹、仅源码而无标记的文件夹不会自动滥识别，可在「项目管理」以工作区
  相对目录和可读名称登记，不要求 `git init`。登记不自动开启新项目网页读取。
- 新自动名称保留相对层级，如 `NailGlow/backend` 与
  `NailGlow/github-20260919/backend`。长名称保持上限并加稳定摘要。
- 旧版登记缺少名称来源，无法判断 `backend` 是用户自选还是旧默认，不擅自重命名。
  新 `qualified_name` 用于应用显示、网页列表和选择消歧；人工名称、别名、项目 ID
  与读取授权保留。同名或别名冲突仍要求确认，不猜选项目。
- 根项目仍排除独立登记的子项目，即使子项目未启用；名字分组不是权限合并。

## 登记格式与降级限制

新登记文件为 schema 2，记录 `name_origin`。新版可以加载 schema 1，未变化的旧记录
不因只读查询而强制改写；后续本机登记/授权等变更可能把该登记文件升级为 schema 2。
**旧 beta.1 程序不认识 schema 2，不能直接用旧程序打开已升级的登记文件。**

本次没有读写维护者正在运行的真实登记文件。后续安装必须先明确迁移/降级方法；
不得删库或覆盖旧记录来恢复运行。固定 0.4.3 锚点、原 Git 历史和旧持久数据保持不动。
降级时若需要从新格式导出旧格式，应本机明确确认，在验证名称/授权/来源后生成
独立导出，不移动锚点，也不静默重建或自动开权；这项导出本轮没有实现。

## 用户代码回退：已从新源码对外移除

已删除：菜单栏「回退这项任务」、其授权/请求状态、网页 `rollback_write_task` 工具、
desktop-control 和 workspace 的主动回退动作、协调器的公开回退方法。
保留十五项读取工具；任务工具为开始、精准编辑、创建文件、创建目录、删除文件、
完成任务、只读任务状态，共七项。旧客户端缓存调用回退返回不支持，不重新写文件。

保留的不是代码版本管理服务：

- `get_diff` 需要的当前任务起点与有界保留策略；没有起点明确报告不能比较。
- 单文件写入/删除前的持久意图、暂存和校验，防止中断状态被当作正常完成。
- 本机「恢复未完成任务」以及旧 beta.1 已有 interrupted rollback 日志的兼容处理。
  不新增主动回退入口；不能清掉受保护日志、旧库或未知文件来降低空间占用。
- 兼容测试可直接构造旧回退日志；它们不是新 UI/MCP 的可调用功能。

Git 恢复只对已经记录的内容可靠：未跟踪新文件、未保存修改和未提交内容不保证能从
Git 找回。CoLink 不自动 git add/commit/stash/reset/checkout/clean，不承诺代码坏了
一定可回退；用户重要稳定点应另行保存。删除源码前请确认有需要的版本记录。

本决定取代 WRITE_CONTRACT.md、WRITE_IMPLEMENTATION.md 中要求继续提供主动
整项回退的旧产品目标；旧文档/验收保留时间点事实，不回写历史为“从未实现”。

## 验证与尚未完成

测试覆盖自动发现/旧登记格式/权限隔离、回退工具缺失与旧调用拒绝、创建/编辑/删除/
Diff/完成、默认关闭和未完成恢复。旧恢复兼容仍保留定向测试，不跳过来获得绿灯。
验证结果另见 CHANGELOG。本机协议/Swift typecheck 不替代真实新安装版或网页验收。
当前系统应用和网页插件尚未更新，不能把源码修复称为已经在用户界面生效。

随附 Skill 的本机标准校验使用已有环境，不把它的校验依赖加入 MCP 运行依赖。
本机维护者统一使用全局 `validate-skill <技能目录绝对路径>`，校验器不再属于本项目。
入口先检查现有普通/系统/捆绑 Python，找到能导入 yaml 的解释器后调用标准脚本；
不自动安装包、修改 PATH 或开放网页终端权限。其他贡献者可以使用 skill-creator
提供的标准校验脚本与自己的现有 Python；此全局辅助入口不是 MCP 的安装依赖。

本轮生成物集中在 .artifacts 的独立检查目录；默认保留，须列清单并获得用户确认后
才清理。没有自动删除旧数据库、缓存、用户原始代码或未跟踪的样例内容。
