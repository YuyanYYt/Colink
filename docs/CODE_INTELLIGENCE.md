# CoLink 0.4.3 · Python / Java 按需结构查询

这是独立读取增强分支 `codex/colink-code-intelligence` 的功能说明，不是 0.4.1
公开安装包的功能。维护者已安装自包含 0.4.3，并对 Python 自定义源码根的文件依赖、
类类型引用和本地调用完成定向网页验收，见 [验证记录](VALIDATION.md)。尚未公开发布，
不宣称所有新工具、任意项目或新账户都已经验收。
它不会启用写入、创建源文件、执行项目代码或测试。

## 为什么值得做，哪些先不做

原有 `search_code` 返回同名文本，模型需要再区分定义、导入、注释和实际使用。
结构索引可以直接给出定义范围、静态绑定和关系证据，减少为定位而反复读文件。
它不提高模型本身的智力，也不保证所有查询一定更快；首次解析与更新会增加成本。

本轮支持 Python（运行时标准库 AST）和 Java（Tree-sitter Java grammar），不运行
项目 import、JDK、编译器或后台语言服务。其他语言仍可用原有源码读取/文本搜索。
不做全库 UML 页面、ORM 专用关系、向量搜索、第三方源码采集或动态运行时追踪。

## 按问题选工具

| 需求 | 工具 | 返回内容 |
| --- | --- | --- |
| 查定义，而不是同名文本 | `symbol_search` | 符号位置、类型、作用域、语言、内部 ID |
| 读取某个定义 | `read_symbol` | 该位置的实际源码文本和行范围 |
| 谁使用这个定义 | `find_references` | 静态绑定的导入、调用、类型等使用位置 |
| 谁调用它 / 它调用谁 | `get_call_graph` | incoming / outgoing / both，调用及构造证据 |
| 继承、实现、成员、类型使用 | `get_class_graph` | 类与接口的有类型关系，不一次导出全库 |
| 文件和模块之间为何依赖 | `get_file_dependencies` | consumer → dependency、证据行、正反向链 |
| 底层到上层、哪里循环 | `get_project_architecture` | 依赖优先层级、强连通循环组 |
| 导入的外部依赖候选 | `get_external_dependencies` | 不在镜像中的模块与 used_by 文件 |
| 修改某处可能影响哪里 | `get_impact_analysis` | 有限深度反向依赖；可加符号直接引用证据 |

原六个工具保留，合计十五个只读工具；均不具备命令执行、源目录写入和 Git 写入能力。
使用者通常只需自然提问，不需要知道工具名称。AI 必须先取得 `repo_overview` 的
读取标识，同一次分析复用它，按需调用结构工具并读取实际源码验证结论。

例如：“这个 Document 类谁继承？”只查类关系；“修改 models.py 会影响哪些文件？”
查反向依赖/影响；“这个方法做什么？”先定位，再读源码，不顺带导出全部关系图。

## 静态证据的边界

- 精确定位来自语法解析和已授权镜像；跨文件目标来自可见模块、导入和词法作用域。
- Python 相对导入、别名和可见重导出可以绑定；参数/局部变量同名不会自动连接到
  别处定义。动态对象、动态导入、反射、运行时 monkey patch 等可能无法解析。
- Java 可见 package、import、类型及成员支持静态关联；同名重载即使参数个数相同
  也不能仅靠名称确认。声明类型只提供可能分派目标，不等于实际运行时实现。
- `resolved` 表示给定静态规则找到唯一候选，不表示编译/运行通过。
  `unresolved` / `ambiguous` / `unavailable` 明确保留，不猜测目标、不填伪置信分数。
- 外部依赖列表不是已安装库清单：缺失导入还可能是被忽略的本地文件或拼写错误。
  不推断包版本、不声称已经检查第三方库源码。
- 层级按文件依赖计算，循环先缩成组；不是自动推断出来的业务架构。
  影响分析是潜在范围，不能代替源码核验或测试，也不代表可以安全自动重构。

## 热更新和一致性

源目录 → 既有生产端/持久化 outbox → MirrorStore 事务 → 源码＋索引 → 只读工具。

索引生成发生在生产端提交时，不在 MCP 查询时扫描源目录。首次启动为现有保留
状态补建索引；未变内容的解析结果按路径、哈希和解析器版本复用，不长期保存 AST。
普通函数体改变且绑定拓扑不变时只重解该文件，其余关系复用；定义、导入、作用域
或模块结构变化时重新绑定全项目静态关系，但仍不重新解析未变源码。

源码和关系在同一事务中提交；意外存储/实现错误整体回滚，解析失败则记录覆盖限制
并保留普通源码读取。索引查询在单一读事务中解析 snapshot 和读取全部相关事实；
不会把旧源码和新关系混合。过期标识明确要求重新分析，不静默改读当前。
查询只读，不触发采集、清理或构建。同步协议与源镜像 schema 仍为 1 / 2，
派生 `ci_*` 表按独立绑定索引版本回填，解析缓存仍按解析版本复用；旧版读取端的
快照清理可通过外键级联清理关系。

## Python 源码根目录

项目根目录不一定是 Python 的 import root。比如文件在
`Code/agent_runtime/models.py`，而源码导入 `agent_runtime.models`，就需要按 `Code/`
作为源码根建立模块映射，不能只把完整文件路径的斜杠替换成点。

本轮修复在已授权镜像内按以下规则建立候选，不执行 import、不探测宿主机的
`sys.path`，也不采集配置所提及的新目录：

1. 显式配置优先：读取该份镜像根目录 `pyproject.toml` 的 `[tool.colink]`。
2. 未配置时，以连续 `__init__.py` / `__init__.pyi` 包边界和已观察到的绝对导入
   联合识别自定义根，支持 `Code/`、`backend/`、`services/foo/src/` 等非硬编码名称。
3. 保留项目根和常规 `src/` 布局回退；若 `src/` 本身是普通包，不自动剥掉其包名。
4. 多个根中的同名模块返回 `ambiguous`，不按配置顺序、目录名字或文件后缀猜目标。
   不使用任意路径后缀匹配；证据不足的自定义 namespace 根需显式配置。

例如可在目标项目现有 `pyproject.toml` 中填写（CoLink 不会替用户自动编辑该文件）：

```toml
[tool.colink]
python_source_roots = ["", "Code"]
```

`""`（或 `"."`）表示已选择的项目根。配置是完整替代集合，不与自动发现的根混用。
多根可写 `['backend', 'python']`；显式根也支持没有 `__init__.py` 的 namespace
包文件映射。这里只处理镜像内的具体文件，不宣称复刻 Python 的运行时搜索路径优先级、
虚拟 namespace 对象或自定义 import hook。

根路径必须是规范化的项目内相对 POSIX 路径，不接受绝对路径、`..`、反斜杠、控制
字符或超过 1024 字符的根；最多 32 个根，配置文件解析预算 64 KiB。错误配置只返回
通用诊断并将索引标为不完整，仍可读取源码；不回显配置值、异常文本或访问目录外文件。
自动识别超出根数量预算时仅保留回退规则并说明限制，不任意挑选一批根冒充完整结果。

根目录或包边界改变会重新绑定未变化的导入文件，未变化源码仍复用解析事实；同一
snapshot 的配置、源码和关系保持一致。派生索引版本已更新，启动时为当前与前一份
保留状态重建关系，不增加源码历史份数，不改变读取标识或原始同步协议。

这一修复同时恢复依赖图、调用/类关系、引用、层级和影响分析所依赖的本地模块绑定。
它不意味着所有动态类型、反射、运行时导入或外部库符号都已经可以解析。

## 防止无界增长和响应膨胀

- 跟随已确认规则，每个项目只保留当前＋前一份源码/索引状态。无引用解析缓存在
  生产端提交时清理；没有每改一段就永久留一份索引或副本。
- 单文件结构解析上限 4 MiB、250000 节点、5000 符号、20000 引用。
  超限文件仍可普通读取，索引状态说明 resource_limited。
- 每份状态的解析缓存有效载荷最多 32 MiB、物化符号/关系有效载荷最多 32 MiB、
  符号和关系合计最多 100000 条；超限时说明 `index_partial`。这不是数据库文件
  硬上限：SQLite 行、索引、页和 WAL 还占空间，长事务可能延后回收。
- 图默认一跳、50 节点、100 边；符号图/文件图最多五跳、200 节点、500 边。
  架构视图最多 500 文件和 1000 边。默认响应字符预算 20000，最大 50000。
  截断必须明确；可分页或缩小范围，不能据截断内容声称完整审查。
- 这些规则只清理派生快照/索引记录，不删除数据库本体、配置、密钥、源码、依赖、
  测试结果或安装产物。普通回答不显示递增内部编号。

## 大项目读取配额

| 范围 | 0.4.1 | 0.4.2 开发版 |
| --- | --- | --- |
| 单个允许文本文件 | 1 MiB | 4 MiB |
| 项目全部允许文本 | 8 MiB | 128 MiB |
| 项目允许文本文件数 | 10000 | 50000 |
| 同步 JSON 请求 | 20 MiB | 256 MiB |

这不是无限额度，也不解除秘密/二进制/符号链接/忽略目录等过滤。超额总项目拒绝该次
提交，保留之前的完整状态；超大单文件在扫描结果中给出跳过原因，不承诺任意仓库全量可读。
“允许文本”不包括 node_modules、.git、构建产物等强制排除文件。

本轮没有把一次完整同步拆成多个可见批次。那样会让“前一份代码”变成中间状态，
破坏两份完整项目状态的比较语义。现有协议仍一次原子提交，首次同步大项目可能耗时
并暂时占用较多内存；需要更大规模时再设计暂存分片＋最终原子发布，不能冒充已经实现。
网页查询不一次返回全库；`read_file` 的文本页默认 20000 字符，最大 50000，超长
单行可用 `next_start_line` 和 `next_char_offset` 继续读取；`read_symbol` 使用
`next_line_offset` 和 `next_char_offset`，确保字符预算下续读不跳过或重复内容。
