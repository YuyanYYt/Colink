# CoLink · MCP 受控写入契约

记录日期：2026-10-05。性质：后续开发的功能与验收基线，不是已实现能力。

后续状态说明：独立读取增强分支 `codex/colink-code-intelligence` 已开发 0.4.2 的
Python / Java 按需关系查询。本契约仍保留写入方案记录时的六工具与容量基线；新增
只读工具及 4 MiB / 128 MiB 读取配额不自动扩大未来的写入、备份或恢复预算。
写入实施前须重新核对读取能力并确认写入额度；本轮不实现或授权任何写入工具。

## 2. 必须完成的功能

| 编号 | 功能 | 必须满足的结果 |
| --- | --- | --- |
| W01 | 保持读取能力 | 六个只读工具、原有目录范围、热更新、当前/前次两份镜像及不透明 snapshot 语义不回归 |
| W02 | 本机写入开关 | 菜单栏增加“允许修改当前文件夹”，默认关闭，后台实际拒绝未授权写入 |

| W05 | 精准编辑 | 按指定行之前/之后插入、替换行范围、精确匹配替换代码段；有冲突或歧义时拒绝 |
| W06 | 先保存再写入 | 必要副本与恢复记录持久保存且校验通过后，才能修改真实源码；备份失败则源码不变 |
| W07 | 跨轮任务与关系记录 | 多轮对话、多个文件可以属于同一任务；记录任务—文件—操作—内容状态的关联 |
| W08 | 整项任务回退 | A、B、C 分轮修改后，可一起恢复至任务起点，不只撤销最后一轮或最后一个文件 |
| W09 | 幂等与中断恢复 | 重复请求不重复插入；崩溃、响应丢失和重启后能区分未写入、已写入、待恢复 |
| W10 | 写后热更新协调 | 写入真实源码后由原生产端更新镜像；不把修改前 snapshot 或半完成状态冒充写后结果 |
| W11 | 有界恢复区 | 副本、关系记录、请求记录和临时数据都有额度与回收规则，不能按编辑次数无限累积 |
| W12 | 实际客户端验收 | 分别验证本地核心、菜单栏、安装包、网页读写回退和 Skill；一种证据不能代替另一种 |

首版不包含任意终端执行、运行项目、安装依赖、整机控制、普通文件删除/移动/重命名、
新增来源目录、多用户或公网权限系统。恢复时撤销本任务创建的文件/空目录，是整项
回退的受限组成部分，不是通用删除能力。

打开写入开关不等于授权 AI 主动改项目。解释、审查、调研仍然只读；只有用户明确
要求创建、修改或实现时才进入写入工作流。暂不建设复杂审批系统，不等于省略路径、
内容、备份、幂等和冲突检查。

## 3. 本机开关与客户端权限

1. 每次启动连接默认关闭；连接未就绪或存在未完成恢复时，不得正常开启新写入。
2. 开关只授权当前选择的目录与当前连接，网页工具不能自行打开。
3. 后台确认权限变更后，界面才显示成功；不能仅改变开关外观。
4. 关闭先拒绝新请求。已经进入提交阶段的操作须完成或记录可恢复状态，不能无日志
   中断；关闭开关本身不撤销已完成修改。
5. 停止、退出、重启、切换目录、连接异常或控制通道失效后，旧写入授权失效。
6. 普通开关切换不要求重新刷新工具列表；首次新增/更新工具后再刷新客户端并验证。
7. Colink 的目标是在本机开启后不增加逐次确认弹窗；网页端按用户选择的确认设置
   配合，不能由 Colink 承诺永不出现平台确认，也不能伪装只读工具来绕过它。

官方开发者模式说明支持读写工具，写入默认需确认，也描述了对话内记住选择及新对话/
刷新后重新确认的行为。因此“连续操作减少弹窗”必须作为实际网页验收项目，不能
视为平台不变的保证。[ChatGPT Developer mode](https://developers.openai.com/api/docs/guides/developer-mode)

新增变更状态的工具必须如实标记非只读；MCP 注解和 Skill 都不能替代服务器授权与
参数校验。[官方工具注解说明](https://developers.openai.com/plugins/build/mcp-server)

## 4. 精准写入契约

修改已有文件的请求必须关联：当前项目、任务、不逃逸的相对路径、读取时的完整文件
内容校验值、明确修改位置/原内容、新内容和唯一请求标识。名称与 schema 待实现定稿。

- 行号从 1 开始；替换范围包含起止两端；插入明确“之前”或“之后”。文件开头、
  末尾和空文件须有无歧义定义，不能默许越界行号。
- 行号只负责定位，不能单独授权修改。提交前核对真实磁盘内容及目标原文/上下文，
  旧行号、旧校验值不能强制覆盖新文件。
- 代码段替换必须精确匹配；零匹配或多匹配均拒绝，不做模糊猜测替换。
- 复用现有文件过滤、容量、来源绑定和 nofollow 边界；拒绝越界、符号链接绕行、
  密钥和不支持的文本。不顺带放宽单文件 1 MiB、项目总文本 8 MiB 的现有限制。
- 保持未修改部分的原始内容、换行和必要文件属性；不因写入重新格式化整个文件。
- 新文件目标已存在时拒绝；已有目录不认作本任务创建。目录创建的重试语义与所有权
  必须明确，不能借重复请求覆盖或重新取得已有对象的所有权。

执行顺序固定为：

```text
检查本机授权、任务状态和路径
→ 读取磁盘并核对目标内容
→ 检查并预留恢复/临时写入空间
→ 持久保存必要副本和操作记录，校验可恢复
→ 准备新内容，提交前复核源文件
→ 替换源文件并读回验证
→ 持久记录结果，通知原有同步生产端
→ 返回本地结果和镜像确认状态
```

不能先截断原文件再慢慢写，也不能先覆盖后才从镜像中寻找副本。Colink 自身写入
串行协调，但不能把自身锁或一次哈希检查宣称为对所有外部编辑器的完整并发保护；
提交时竞态须专项验证，无法保证时拒绝或报告待恢复状态。

## 5. 任务、关系图与版本标识

任务是恢复单位，不是对话轮数。用户的一项功能修改可以跨多轮、多文件，写入继续
携带同一不透明任务标识，直到明确完成或回退；不能因为又发了一条消息就自动另建任务。

任务起点建立允许文件的基线清单、内容校验值及来源身份。文件首次被本任务修改前，
保存其任务起点内容；同一文件后续多次修改不得覆盖起点副本。不要求每轮复制整个项目。

稍后加入任务的文件必须与起点基线一致；若已被外部修改，不能把晚到的副本冒充任务
起点。应报告冲突，由用户决定处理方式，不能静默重设基线。

| 关系 | 首版职责 | 边界 |
| --- | --- | --- |
| 任务与文件 | 记录实际修改、新建的文件/目录及所有权，决定整项恢复集合 | 未修改文件不能因依赖关系被顺便覆盖 |
| 文件内容与操作 | 保存起点、各次操作前后校验值、先后顺序、请求标识和持久状态 | 内容关系不要求保存每个中间状态的完整源码 |
| 代码静态依赖 | 记录能够确认的 import/引用关系与来源，辅助提示影响范围 | 未覆盖语言和动态关系标为未知；不是完整调用图保证，也不作为唯一回退依据 |

首次完整写入交付必须具备可靠的任务关系和内容关系。具体语言的静态依赖覆盖在实施时
明确，更多语言与复杂依赖分析作为后续增强；不能把关系分析不完整当作漏恢复文件的理由。

软件发行版本、任务检查点、文件内容校验值、内部同步 revision 各自独立。普通代码
回答只解释改动和验证结果，不展示递增版本号、任务 ID、snapshot 或哈希。

## 6. 整项任务回退

示例：第一轮 A₀ → A₁，第二轮 B₀ → B₁，第三轮 C₀ → C₁。三轮属于同一任务；
回退后恢复 A₀、B₀、C₀。同一任务中 A₀ → A₁ → A₂ → A₃，仍恢复 A₀。

首版支持当前任务，或最近一项仍在保留期内、没有后续任务压在上面的已完成任务。
撤销更早任务并保留后续修改属于选择性撤销，不纳入首版整项回退承诺。

回退也属于写入，须遵守本机开关、来源范围、空间和冲突检查。步骤为：

1. 在开始恢复前检查全部目标文件，必须仍为该任务最后写入的状态；发现外部修改则
   报告全部已知冲突，不先恢复 A 再强制覆盖存在冲突的 B。
2. 预留空间，准备全部恢复内容，保存必要的回退前副本与可继续的恢复日志。
3. 逐文件执行恢复，提交前复核并记录进度；过程中发生冲突或失败，保留恢复材料，
   明确报告已执行范围和待恢复状态，不能谎报整项成功。
4. 删除仅由本任务创建且未被外部改动的文件；本任务创建的目录仅在仍为空且所有权
   可确认时移除。已有文件/目录和外部后来加入的内容不得被删除。
5. 验证全部恢复结果，统一发布本次回退的最终镜像，再进入终态。

中途退出后，下次启动必须识别未完成恢复，写入授权保持关闭，提供受控恢复入口。
不能把 SQLite 日志事务等同于日志与多份源文件的原子提交。单文件替换不代表多文件
同时对外变化；Colink 不发布本次操作半完成的镜像，但外部编辑器或项目热重载仍可能
观察到逐文件变化。

本契约承诺源码恢复，不撤销代码已经造成的数据库更新、网络请求等运行副作用。
“撤销回退”或任意历史选择性合并不是首版必备功能；回退前材料仍需按恢复和容量规则管理。

## 7. 读取、同步与往返延迟

原读取工具继续只查询镜像，不负责采集、备份或写源文件。写入器独立于镜像更新
接口；修改镜像数据库不算写入了用户源码。写后由原有生产端优先对账，不新建竞争的同步链路。

- 已有充分代码上下文和有效校验值时，可以直接提交修改；本机内部仍读取、校验、
  备份，不要求网页额外调用“备份工具”。
- 上下文不足、内容冲突或要修改未读过的部分时，重新读取必要范围，不机械读取整仓。
- 写入结果应返回受限的实际修改片段、新文件校验值、本地读回结果和同步状态，供
  后续操作使用；需要更多上下文或独立验收时再调用读取工具。
- 本地写入成功但镜像尚未确认时，明确区分两种状态；不能用普通“失败”引发重复
  插入，也不能宣称网页已经读到新内容。验证修改必须使用新的读取状态。
- 一次写入/回退操作未完成时，不发布其半完成镜像。多轮任务中已完成的一轮可以
  正常热更新，不冻结整项任务直至所有对话结束。
- 幂等请求关联来源、任务与内容；相同请求不重复执行，同 ID 不同内容拒绝。过期
  任务/请求明确拒绝，不能在记录清理后把旧请求当作全新写入重新执行。

本机校验、备份、写入、同步确认和完整网页往返分别计时；没有实现后的测量结果前，
不承诺具体毫秒数，也不宣称必定比 Git 快。APFS 克隆可作为优化研究，不是恢复
正确性的前提，不使用会随源文件一起变动的硬链接充当独立副本。

## 8. 有界恢复区与建议预算

恢复副本独立于“当前/前次”读取镜像，放在 Colink 专用私有数据区并排除采集；
不在源码旁生成大量 `.bak`，不操作用户项目的 Git 索引、提交或 stash，不执行 git reset。
可以借鉴内容寻址与引用计数，但采用何种数据库/副本格式不在本轮确定。

以下沿用上次讨论的**建议默认值，仍待实施确认**：

| 项目 | 建议规则 |
| --- | --- |
| 活跃任务 | 全局最多 1 项，中断待恢复任务也占名额 |
| 已完成恢复点 | 最多最近 1 项 |
| 已完成恢复点期限 | 完成后最多 7 天 |
| 常驻恢复预算 | 64 MiB，计入副本、关系记录、幂等信息及操作元数据 |
| 受管理峰值预算 | 128 MiB，计入必要临时副本、恢复准备文件、数据库/WAL 等附属文件，并预留文件系统余量 |
| 单任务操作次数 | 最多 1,024 次，达到上限后拒绝新操作，不自动拆任务绕过上限 |
| 配额范围 | 整个 Colink 恢复区共享，切换项目不再发放一份独立无限额度 |

预算不是整个应用、源码工作区或所有磁盘占用的保证。镜像、恢复区和测试/发行产物
必须分别计量；删除数据库记录不等于文件立即变小，需验证空间回收与 WAL 管理。

确认并实现规则后，只有明确登记在恢复区内且不再受保护的数据才可自动回收：

- 新任务完成并接受后，超出保留数量的旧完成恢复点；超过保留期限的完成恢复点。
- 已成功结束、不再用于中断恢复的操作临时副本。
- 没有任何保留任务/恢复点引用的内容对象；共用对象只有最后一个引用消失才删除。

活跃、冲突待处理、正在回退或中断待恢复任务的必要材料，不能因超时或容量压力
删除。保护材料持续占据额度时应停止接受新写入，不以“先丢备份再写”维持运行。
清理后空间仍不足，也必须拒绝新写入并保留现状。

同一任务内一个 100 KiB 文件小改 300 次，任务起点只留一份，中间成功操作的临时
完整副本可回收，操作关系受数量与容量约束；**不能永久保存 300 份完整内容**。
总体占用还包括两份读取镜像、元数据和临时空间，不承诺恰好 200 KiB。

这套未来恢复区策略不是对现有文件的删除授权。本轮及后续测试/构建产物仍按
`AGENTS.md` 先列明、再确认；源码、配置、凭据、数据库本体、锁文件、旧应用和
用途不明文件不进入恢复区自动清理范围。

| 0.6.0 候选 | 更多语言依赖分析、研究选择性撤销 | 另行设计合并/冲突与容量规则，另行确认，不是当前必须实施的范围 |

开发时正常使用源码提交，不为每次小修改打包；达到应用联调/发行节点再构建。
本地完成、安装到维护者电脑、推送 GitHub 和公开 Release 是不同交付动作，不能
因本契约自动执行，也不覆盖历史安装包或挪动锚点。

## 10. 必须记录的验收证据

1. 六个原只读工具、热更新、停机编辑恢复、两份镜像保留与过期拒绝全部回归通过。
2. 文件头/中间/末尾/空文件插入、单/多行替换、唯一代码段替换、中文/换行与文件
   属性正确；零/多匹配、非法范围、越界与符号链接明确拒绝。
3. 默认关、打开、关闭、停止、退出、切换目录、重启和通道失败时的真实后台行为；
   网页不能自行开启，也不能凭缓存工具绕过。
4. A/B/C 三轮修改一次整体恢复；同文件反复修改仍回到任务起点；未修改的依赖文件
   不被覆盖。稍后加入文件与外部编辑冲突均正确拒绝。
5. 新建文件/目录的任务所有权与回退行为；后来被外部改动、填入内容时不误删除。
6. 备份失败、磁盘不足、预算超限和操作次数超限时不继续改源码，仍保留恢复材料。
7. 写入/回退阶段崩溃、响应丢失和重启恢复；重复及过期请求不重复落盘；不得把部分
   恢复误报为全部完成。
8. 100 KiB 文件 300 次小改不累积 300 份永久副本；核对常驻和峰值实际占用、WAL、
   临时文件与清理后空间效果，不只数数据库中的记录。
9. 原有同步生产端独立推进，写后新状态可读，镜像待确认明确报告；不使用旧 snapshot
   验证新代码，不发布同一次写入/回退的半完成状态。
10. 真实菜单栏和真实网页分别验证多轮任务、完成、回退与关闭拒绝；Skill 增加只读
    反例与多轮关联指导，但不把“已写好 MD”当作自动调用或权限已通过的证明。
11. 安装/升级保留已授权目录、连接身份、凭据和数据库，写入重新关闭；公开文件无
    真实凭据或用户代码。所有测试使用新的独立目录，不修改真实业务项目。

待正式实施时运行 `uv sync --locked`、Ruff、相关/全量测试及原有端到端 demo，并
补充写入/回退专项演示。结果、限制和保留产物进入 CHANGELOG 与验收文档，不能
在代码尚未实现时宣称本契约已经通过。
