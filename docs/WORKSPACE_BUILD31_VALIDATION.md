## 文件读取规则核对

用户粘贴的原因与本机复现一致：3 个数据库模块命中整文件密码赋值正则，
`tests/test_database_discovery.py` 命中凭据 URL 和密码默认值正则。均远小于 4 MiB，
实际 SourceAccess 返回 `FILE_EXCLUDED`。本机 AST 复核发现赋值表达式、动态模板和
测试样例也被原始文本正则识别；命中诊断只保存规则、行号和语法类别，不保存匹配
片段。没有修改过滤规则或默认放行测试文件。

## 数据流评估

结构索引持久化，M2 数据流仍按请求计算。每种模式与场景原方案/仅基准进程内的
精确源码 AST 复用原型交替各 50 次，结果等价。包括完整本地 Live 源码校验，不含
网页、模型、网络或电池测量。

| 合成场景 | 原方案热查询 P95 | AST 原型热查询 P95 | 观察 |
| --- | ---: | ---: | --- |
| 151 B 单文件 | 3.10–4.12 ms | 3.07–3.80 ms | 几乎没有收益 |
| 1001 文件，目标 151 B | 79.20–81.63 ms | 79.67–87.28 ms | 没有稳定收益；源码校验主导 |
| 291 KB 目标，4000 个无关方法 | 92.34–100.56 ms | 36.81–55.37 ms | 各模式 P95 下降约 45%–60% |

已核对源码改变后旧上下文拒绝、刷新后重新解析且路径结果改变；重启复用结构库
但重新解析数据流 AST，无新数据流持久表。大目标 AST 原型另留约 17 MB Python
分配，清空后释放；诊断使用 GC，不向产品加入每次请求 GC，也不等同于进程 RSS。
保留当前按请求计算，暂不持久化完整图。大型 Python 文件的重复查询存在缓存潜在
收益，但方法摘要还需独立验证调用上下文、参数、副作用及依赖失效，当前未实现。

证据在 `.artifacts/workspace-cleanup-20261011/dataflow-performance/`。
一次性测量脚本保存在同轮 `benchmark_dataflow_components.py`，从项目根运行；
隔离源码已清理，重复实验应选择新的输出目录重新生成，不能直接 resume 已清走
的来源。性能 JSON 与逐次样本保留。
