## 2. 本地离线恢复材料

同一个恢复目录只保留一份本版应用压缩包和一份源码 Git bundle：

```text
.artifacts/anchors/colink-0.4.3-before-live-workspace-refactor/
├── CoLink-0.4.3-source.bundle
├── CoLink-0.4.3-macos-arm64.zip
├── SHA256SUMS
└── RECOVERY.md
```

bundle 包含锚点 Git 对象和可恢复的源码历史；ZIP 来自当前已安装的自包含应用，
不是重新编译，也不需要先重新下载依赖才能恢复这份程序。保存时核对应用后端与
源码一致、应用签名、包扫描、ZIP 完整性和 SHA-256；实际结果见
[验证记录](VALIDATION.md)。这不是重新进行全套 macOS 安装或网页端验收。

这些本地恢复材料被 `.gitignore` 排除，不上传公开仓库。ZIP 不包含个人配置、
凭据、镜像数据库或所选项目源码。运行数据继续保留在 Application Support/Colink；
这份锚点不是运行数据库备份，不能恢复未另行保存的数据。

## 3. 必须保留的已有能力

1. 单个已授权目录是代码来源，当前仍使用监听、同步和只读镜像，不执行项目代码。
2. 现有十五个 MCP 工具保持只读；文件/源码分页、搜索、差异和连接状态可用。
3. Python / Java 符号、引用、类关系、调用关系、文件/模块依赖、外部依赖、
   依赖层级/循环和潜在影响查询保持静态证据、不确定性和响应预算。
4. Python 自定义源码根绑定、显式根配置、多根歧义、配置变更与旧索引回填保留。
5. 首次完整同步、后续增量、持久化 outbox、幂等重试、断网/重启和来源保护不回退失效。
6. 当前＋前一份源码状态、去重及派生索引留存有界；一轮查询不混读不同 snapshot。
7. 普通问答不暴露递增版本编号。应用启动/关闭/选择文件夹、菜单栏、重新打开入口保留。
8. 原 bundle ID、数据路径、私有连接身份、目录选择、凭据与既有授权范围不改变。

多项目工作区、原文件直读和受控写入是已保存的待实施方案，**不属于本版已实现能力**。
[读取重构计划](LIVE_WORKSPACE_REFACTOR.md) 与 [写入契约](WRITE_CONTRACT.md) 仍须按阶段验收。

## 4. 重大问题后的执行顺序

当重构导致原读取/同步无法恢复、跨项目或来源隔离失效、持久数据被破坏、容量失控，
或新路径存在无法及时控制的重大回归时，停止推进新路径，以此锚点为恢复目标。
当前正在运行的应用不因保存锚点而重启、更换或改变连接状态。

1. 先停止有问题的新连接；如果后续已有写入能力，同时关闭写入，防止继续扩大影响。
2. 保存故障版本的源码、提交/未提交改动和必要诊断，保留它们用于排查；不删除重构成果。
3. 在独立恢复分支/checkout 使用固定标签，不用 `git reset --hard`、强制 checkout 或
   移动标签覆盖当前工作。以下仅在确认工作树干净且分支不存在时使用：

   ```sh
   git status --short
   git switch -c codex/colink-recovery-043 anchor/colink-0.4.3-before-live-workspace-refactor
   ```

   有未提交工作时，先完整保留它们；优先独立 checkout，不为切换而丢弃文件。

4. 在隔离样例验证源码或保存的应用包。需要恢复安装版时，先退出并确认新版本的
   自有进程已停止，再保留待排查的新应用并使用本版 ZIP；不覆盖运行中的解释器。
   遵循 [安装指南](INSTALL.md) 的身份、路径与安全检查，不取消安装脚本的拒绝覆盖保护。
5. **检查运行数据兼容性后再启动。** 旧程序不应直接打开被重构版本升级到不兼容
   schema 的数据库；必要时使用升级前的独立数据备份。若没有可恢复的数据或兼容
   路径，先说明限制，不盲目降级或删除数据库来“修好”启动。
6. 核对原目录、私有连接与默认关闭边界；经用户需要再恢复原连接。若网页工具描述
   已随重构变化，刷新原连接并实际验证原读取能力，不另建更广权限的连接。

源码回退不等于撤销用户项目文件、已执行命令、外部服务副作用或数据库迁移。
未来写入的多轮多文件恢复由写入契约的任务恢复区负责，不以 Git 软件锚点代替。
