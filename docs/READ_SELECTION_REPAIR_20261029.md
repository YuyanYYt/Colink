# 读取预算与符号选择修复

## 缺陷与证据

用户网页测试报告了读取预算超限与 SYMBOL_NOT_FOUND，但最终回答没有提供完整请求参数。
因此不能确认当时每一个输入，也不能将新复现称为逐字重放。

在原项目保持只读、使用全新独立索引的安装版 build 36 SDK 实测中：

- `read_code` 的 `max_chars=100000` 被 INVALID_READ_BUDGET 拒绝。
- Java `类.方法` 选择器没有参数签名时返回 SYMBOL_NOT_FOUND，完整签名能够定位同一方法。
- 真正不存在的符号也被包装成工具失败，缺少能继续查找的正常结果。

## 修改后的行为

合法 JSON 安全整数超过读取上限时，按 50000 执行并返回 `response_budget`：
`requested_max_chars`、`effective_max_chars`、`adjusted=true`。
这段元数据在读取和分页前计入预算，整个 JSON 响应仍受 50000 字符硬限制。
正常预算响应结构不变；布尔、字符串、浮点、超安全整数、过低预算和非法时间仍拒绝。

Java 选择器先匹配完整 qualname。在没有签名的 `类.方法` 无精确匹配时，仅在当前项目、
当前事实版本和指定文件中按完整类方法前缀匹配 Java 方法或构造器。
唯一时使用该事实；多项时返回所有重载的有界候选页；大小写、类、文件或名称错误不做模糊猜测。
失效 symbol_id 不会自动重绑定。

合法查询无匹配时，主选择器返回 `analysis_status=selection_not_found`，目标返回
`analysis_status=target_not_found` 与 `selection_scope=target`。
这是未完成选择的结果，不代表源码不存在或两端没有路径。
返回当前符号搜索指引；能够从名称构造有效搜索时提供公开 `read_code` 下一请求，
失效 ID 则要求先搜索当前定义。没有选择成功时不附带错误候选的源码。
普通符号读取使用 `read_status=selection_not_found`，避免错误地标成索引未就绪。

mode 保持隐藏；日常自动路由、兼容策略、工具数量、授权和源码变更校验保持原契约。
此项不扩展跨语言或异步值传播，也不会把 partial 结果改标为完整分析。
