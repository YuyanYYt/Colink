# Colink · 功能大改前锚点

日期：2026-10-05。按用户要求把完成本地修复与验证的 **0.4.1** 固定为锚点，
不在这一轮开始功能性重构。

## 如何识别与使用

- 本轮本地 Git 标记：`anchor/colink-0.4.1-before-refactor`。
- 改动前已发布基线：`v0.4.0`，提交 `564dd8c16ea89058f4ff574a2f096dded788fdd5`。
- 0.4.0 标签和已发布包不修改。0.4.1 锚点不等于已推送 GitHub、新的公共 Release
  或 ChatGPT 公共插件目录发布，远程分发另行执行。
- 确认锚点提交：`git rev-parse anchor/colink-0.4.1-before-refactor^{commit}`。
- 后续新分支从这个锚点起，例如
  `git switch -c codex/colink-functional-refactor anchor/colink-0.4.1-before-refactor`。
  有未提交改动时先保留工作，不强制切换、不使用 hard reset。

若未来修复锚点之后的独立问题，创建新的提交/新标签，不移动这个标签。需要回看原实现
时优先独立分支/checkout，保留当前工作和用户运行数据。

## 重构必须保留的能力与边界

1. 指定目录是代码来源；只读 MCP 不执行命令、不修改源目录、不增加访问范围。
2. 程序启动/关闭由用户明确操作；打开应用不自动共享，关闭停止自己拥有的进程树。
3. 首次完整同步、后续增量、持久化单批 outbox、固定请求幂等重试、冲突失败关闭。
4. 启动和周期对账、停机编辑恢复；源监听失败时拒绝源码查询，不伪装最新。
5. 当前与前一次两份内容、内容去重和过期回收；不能因重构重新无限保留历史。
6. 一轮读取复用不透明 snapshot；过期明确重做，不混读；普通问答不展示递增版本编号。
7. 双端基础过滤、不跟随符号链接、身份与来源隔离、响应与项目容量上限。
8. macOS 菜单栏和毛玻璃面板、启动/关闭/选择文件夹、系统应用入口可重新打开。
9. 已授权的用户目录选择、连接身份、私有凭据和数据库在升级/回滚时保留。
10. 本机测试、发行包、实际 UI、网页调用和自动 Skill 激活分别记录，不能互相替代。

## 锚点包含哪些改动

[核验表](AUDIT_0.4.1.md)、[更新记录](../CHANGELOG.md) 和
[Skill 流程](CHATGPT_SKILL.md) 是本轮具体范围。核心是修正初始差异与错误引导、

索引、多用户、源码写入或快照租约。

## 运行与网页的实际边界

当前 `/Applications/Colink.app` 仍为 **0.4.0** 且连接正在运行。用户先保持锁屏，
这一轮不停止或覆盖该安装版；源码改动不会自动进入其自包含运行环境。
0.4.1 新包单独输出到 `.artifacts/releases/colink-0.4.1-anchor/`，是否构建/验收通过
以 [验证记录](VALIDATION.md) 为准。

网页 Skills 入口和编辑器已核实；本机 Skill 有效不代表网页已安装。锁屏结束后仍需：
安全更新当前应用 → 刷新原 Colink 连接工具 → 创建/启用独立 Skill → 新对话验证自然
提问自动调用与不应调用的反例 → 在授权范围内验证源码改动后的响应。

更新前先关闭/退出原应用并确认连接停止，把旧应用移到确定的新备份位置再安装新包；
不要覆盖仍在运行的解释器/客户端，也不要删除 Application Support 中的配置或数据库。
安装脚本故意拒绝覆盖；需要更新不应取消这个保护。

## 产物与数据保护

新测试目录、两套 demo、Skill ZIP、新安装包和构建验证副本均保留；不自动清理。
若后续要省空间，列出确切路径及用途，再按用户确认范围处理。源码、配置、凭据、
数据库、锁文件和用途不明文件不属于可直接清理的中间产物。
