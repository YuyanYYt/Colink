# CoLink · 工作区直读与受控写入实施记录

开始日期：2026-10-06。用户已授权执行完整读取重构与写入契约，不再仅记录设计。
结束条件仍为功能正常引入且真实网页完成读写、跨轮整体回退和关闭拒绝验收。

## 决策与边界

- 开发分支 `codex/colink-controlled-write` 已快进至 0.4.3 恢复提交 `1fc98de`。
- 恢复标签 `anchor/colink-0.4.3-before-live-workspace-refactor` 不移动；遇到难以控制的
  重大回归保留故障节点，以该基线或更早已验证可运行节点重新开始，不强制丢弃工作。
- 所有本次开发写入和测试数据只在本工作目录内；真实网页测试使用
  `examples/sample_project`，不改其他项目、个人凭据或旧持久数据库。
- 先 R1 解耦，再 R2～R6 原文件直读/多项目/索引/桌面交付，再接 W；旧 HTTP/stdio
  镜像入口保留十五个只读工具及两份历史语义，不改成伪实时历史。
- 新直读上下文只保存来源身份和参与文件校验元数据，不保存整库正文；`previous`
  或任意旧镜像历史请求明确拒绝。后续任务 diff 来自恢复材料，不冒充任意历史快照。
- 采用写入契约建议值：恢复常驻 64 MiB、受管理峰值 128 MiB、全局一项活跃任务、
  最近一项已完成恢复点/最多七天、每任务最多 1024 操作。活跃/冲突/未完成恢复不回收。
  源码单文件维持 4 MiB；直读不对整个工作区套用旧整份镜像 128 MiB 正文配额。
- 自动回收仅用于新协调器创建并登记的可再生成索引及已确认的恢复对象；旧数据库和
  本次测试/构建产物不自动删除。没有公网部署、GitHub push 或替换系统安装版的默认动作。
