## 1. 没有整库镜像的 Diff 来源

Diff 需要前后两份内容，不需要一个永久完整源码镜像。

- 普通读取和结构查询继续按需读取实际原文件，当前校验上下文不是历史快照。
- 任务开始记录允许文件的哈希、文件身份和来源；第一次真正编辑前保存该文件的
  起点正文，后续编辑不覆盖它。任务 A/B/C 分轮修改使用同一任务记录。
- 原 `get_diff` 在新模式应比较任务起点副本与任务最后写入状态的实际文件；摘要
  和相关文件 patch 有响应预算，内部 ID 不要求模型展示在普通回答中。
- 新增文件与目录由任务记录所有权。未经本任务修改的依赖文件不加入恢复集合。
- 外部编辑没有事前正文或 Git 基线时，不能还原任意历史 Diff。若外部修改使当前
  文件不再等于任务最后写入状态，应报告冲突，不把未知改动算成本任务改动或无变化。

## 2. 任务范围与起点开销

默认起点记录当前项目全部可读、允许的文件，不把正文写入恢复数据库。超出完整
枚举、元数据、时间或读取预算时拒绝开始任务，不能保存半张清单并继续写。

提供显式任务路径列表作为大型项目的窄范围选项：最多 1000 个相对路径，可同时
声明将创建的新文件/目录。任务只能修改这些声明的路径，不因后续工具多传一个
文件而扩大；若需要更广范围，重新建立明确起点，不能将晚到的当前内容伪装为起点。
默认完整基线准备预算为 15 秒、512 MiB 累计校验文本和 50000 文件；这些限制是
任务准备限制，不限制普通直读整个项目的总文本容量。实际提交前仍读取目标真实正文。

基线逐个文件采样，再校验捕获身份/哈希。它不是全项目同一瞬间的文件系统快照；
外部编辑器不受 CoLink 内部锁控制。文件第一次加入修改必须仍匹配起点，否则拒绝。

## 3. 不保存每个中间版本

恢复区只保留任务起点与未结束操作/回退所需对象，内容哈希去重。成功操作的中间
完整对象在持久结果确认、最后引用释放后可回收；操作前后哈希及关联记录保留，
每项任务新修改最多 1024 次。关闭开关不等于丢弃活跃任务的起点副本。

默认全局恢复预算为 64 MiB 常驻、128 MiB 管理峰值；当前存储组件的元数据页最多
16 MiB，为 SQLite DELETE journal 预留空间，不使用无限 WAL。额度计入真实文件
分配、内容对象、元数据及必要源目录临时文件；不是整个应用或工作区磁盘/RSS 上限。
整体回退前副本也需要预留，不能接受一项注定无法在预算内回退的写任务。

只回收已登记且最后引用释放的对象；未知文件、被改动对象、活跃/冲突/未完成恢复
对象不得为了容量被删除。容量不足就拒绝继续改源码。测试/构建产物不属于自动清理区。

实际本地 100 KiB 连续小改 300 次：约 12.11 秒，恢复区正文对象只剩一份任务起点，
总常驻 925696 字节；整轮回退后起点和一次最新副本两份，总常驻 1032192 字节。
正文外的是有界任务清单、操作/属性证明及 SQLite 页面，不是 300 份应用缓存。
操作元记录仍随本任务次数增长，受 1024 操作、16 MiB 元数据库、全局容量及任务
退休共同限制。该合成 macOS 测试不是实际网页或企业项目延迟，原证据路径见实施记录。

## 4. 请求重试与过期

开始任务使用协调器颁发并持久保存的单次请求票据。任务提交时生成下一张；同票据
同内容重试返回同一任务，同票据不同内容拒绝。旧任务回收后，旧票据不等于当前票据，
不能当成新请求再执行，避免无限保存已退休的请求 ID。

文件操作绑定不透明任务 ID 与稳定请求 ID，活跃任务期间不清其幂等记录。任务回收
后操作因任务不存在明确过期。重启保留任务/操作日志，但不保留写入授权。

## 5. 精准提交与竞态

固定链路为本机授权/任务/路径 → 真实正文和旧内容核对 → 预留 → 起点及必要操作
副本持久保存、核验 → 持久操作意图 → 完整临时文件 → 提交前再核验 → 原子安装/
交换 → 实际读回 → 持久结果 → 索引失效和新读取上下文。

临时对象以本操作专有 `.colink-write-<随机标识>.tmp` 名称保存并登记身份，强制从
读取/索引/监听中排除。不能截断目标再写，也不删除没有本操作身份和内容证明的对象。

macOS 的 `renameatx_np(RENAME_SWAP)` 可将当前目标与准备文件原子交换，交换下来的
实际旧内容仍在临时对象中。交换后核对实际旧对象，可以识别校验与提交之间的变化，
比不保留实际旧对象的盲目 `os.replace` 多一个检查和恢复依据。该策略不宣称为所有
外部编辑器的全局 CAS；检测到竞态时保留材料、报告待恢复，不猜测强制覆盖或自动反换。
新文件需原子不覆盖安装；目录需不覆盖创建并记录所有权。

整项回退先检查全部目标冲突、准备恢复日志和材料，再逐个恢复并记录进度。多文件
不是全文件系统同时原子变化；未结束/待恢复期间不能把部分状态发布为完整任务结果。
