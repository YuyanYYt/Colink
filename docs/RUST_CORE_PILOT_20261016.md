# Rust 独立核心实际试点：2026-10-16

## 本轮结论

当前文件关系图内核不值得直接替换成默认 Rust 后端。算法本身更快，但 JSON 传输、
图发布和既有 Live 查询流程占据主要时间，两组真实语料均未通过预先设定的
完整查询 P95 至少改善 20% 的门槛。保留独立试点与适配器，不迁移 MCP、权限、
写入恢复、源码访问或数据库路径，不覆盖正在使用的 build 33 安装版。

这个结论只针对本轮选择的强连通分量与反向文件依赖计算。语法解析、绑定和数据流
前端未迁移；它不能证明所有 Rust 迁移都无收益，也不证明整体重写值得进行。

## 实际输入与准确性边界

1. 从本轮备份恢复出的当前 CoLink 已保存源码，共提取 201 个 Python/Java 文件
   节点与 662 条已解析文件边；实际源码没有重新生成或放大。
2. [SootUp 官方仓库](https://github.com/soot-oss/SootUp)固定提交
   `ac620ee8a1e8229202db3dcb409bbfabbf3dbeb5` 的 `sootup.core` 模块，
   276 个真实 Java 文件节点与 1,906 条已解析文件边。

两组分别从原有 Python AST / Java tree-sitter 前端建立新的独立 Live 索引，
Rust 接收同一份已授权图事实。强连通分量完全一致；每组选择 50 个真实文件，
对深度 1/3/5 共 150 次反向影响结果与距离逐项一致；完整 Live 返回也一致。
另验证了非法端点、失败加载后原图保留、固定命令白名单和跨语言文件边。

准确性是对共同输入事实的计算等价，不是独立的编译器真值或运行时调用准确率。
两份索引均为 partial：CoLink 快照 190 文件结构 ready、11 文件受限，另 100 文件
未进行结构分析；SootUp 有 262 文件 ready、14 文件部分解析。限制和原始诊断
随结果保留，不能把差分一致改写为整仓完全覆盖。

SootUp 在这里是实际 Java 语料，不是已经接入的分析引擎。SootUp/WALA 的 JVM
深度分析、[Pysa](https://pyre-check.org/docs/pysa-basics/)的模型和环境，以及
CodeQL/Semgrep 的适配仍需后续独立验收，不能由本次图内核试点代替。

## 默认预算下的实际测量

每种算法 50 次内核测量；每组 50 对 Live 请求，Python/Rust 交替先后顺序。
Live 使用架构查询默认预算：100 节点、200 边、20,000 字符，保留源码前后校验、
关系读取、响应裁剪与公开覆盖信息。没有跳过授权/源码校验来换取速度。

| 指标，P95 毫秒 | CoLink 真实源码 | SootUp Java 核心 |
| --- | ---: | ---: |
| 原 Python 图内核 | 0.115 | 0.211 |
| Rust 命令解析与内核 | 0.025 | 0.028 |
| Rust 常驻进程通信与结果 | 0.067 | 0.103 |
| Rust 每次发布完整图并通信 | 0.352 | 0.861 |
| Rust 新进程、发布图、查询和退出，10 次 | 4.214 | 4.902 |
| 原 Python 完整 Live 查询 | 193.664 | 571.624 |
| Rust 替换图内核后的完整 Live 查询 | 206.564 | 578.122 |
| 完整查询改善比例 | -6.66% | -1.14% |

小幅负差异不应被推广为所有场景 Rust 都更慢，但本轮没有获得明确的整体收益。
微秒级算法节省也无法解释或显著改善百毫秒级完整查询。

之前还完成了 500 节点、1,000 边、50,000 字符预算的实际对照：完整查询 P95
分别为 CoLink 1121.382→1151.503 毫秒、SootUp 5516.236→5573.112 毫秒。
高密度图下实际 CPU 采样主要停在 JSON 编码；这提示优先检查关系解码/响应裁剪，
而不是只移植图遍历。采样不等于对所有生产查询的完整耗时分摊。

## 内存与安装复杂度

- 本机最初没有 Rust 编译器。本轮在 `.artifacts/maintenance-20261016/rust-toolchain/`
  内安装最小工具链，没有修改全局 shell 配置或 PATH。
- Rust 1.99.1 / `aarch64-apple-darwin`；首次工具链安装 182.25 秒、保留占用约
  460 MiB；首次 release 构建包含依赖下载共 9.46 秒，构建目录约 20 MiB。
  安装器没有完整记录传输字节，磁盘占用不当作实际下载字节。
- 独立二进制为 368,928 字节，约 0.35 MiB，仅动态链接 macOS `libSystem`。
  终端用户运行预编译二进制不需要 Rust 编译器；本轮尚未完成独立二进制的应用
  包签名/安装验收，也没有把它装进当前应用。
- 分别在新进程加载同一真实 CoLink 图后，Python 单进程当前 RSS 为 37,312 KiB，
  Python 适配器加 Rust 子进程合计 39,968 KiB，增加约 2.6 MiB。Python 进程峰值
  分别约 36.5/36.9 MiB；合计值是固定观察点而非跨进程峰值。
  保留 Python 协调器时，不能用 Rust 单进程内存代替整套应用内存。
