# Rust 规模、批量与完整只读流程实测 · 2026-10-16

本次扩测后，判断应调整为：Rust 值得继续作为独立分析核心推进，迁移单位应包括
完整的只读请求处理；只替换很小的图函数不足以判断收益。仍不能据此决定整体重写。
小图混合调用、常驻完整流程、每次全量读取源码，是三个不同的性能区间。

用户要求收尾后停止扩充语料与矩阵，没有继续调优 Rust 构建。安装版仍为
0.5.0b7 / build 33，2,624 个普通包文件哈希与备份完全相同，严格签名校验通过；
没有覆盖、重启、推送、全量回归或清理。

## 测试范围和可比性

- 机器：Apple M5，10 个 CPU 核心，24 GiB 内存，macOS 27.0.1，Python 3.11.15，
  隔离目录内的 Rust 1.99.1，release 构建。没有更改全局运行环境。
- SootUp 固定提交 `ac620ee8a1e8229202db3dcb409bbfabbf3dbeb5`，可读取结构源码
  2,263 个，10,613 条聚合文件边。含 2,262 个 Java 文件和一个 Python 辅助脚本。
- CPython v3.11.14 固定提交 `cd1c3a6342869b7346c1b5c27b8de9c6ef9c4e69`，可读取
  结构源码 2,083 个。新试验固定根契约仅支持 .py/.java，排除一个 .pyi 后实际测量
  2,082 个文件、10,364 条边、33,541,218 字节源码。没有绕过现有内容策略。
- 真实子集从不同目录交替取文件，字节和 SHA256 对照原文件，不复制放大。子集是
  诱导子图，通往子集外的边被省略。两仓没有伪造跨仓调用边。
- 10,000 / 50,000 节点仅为明确标注的合成模块图，测试 SCC 计算与通信；没有
  声称它们是真实项目、完整源码流程或解析器覆盖。

对照包括旧 SCC/裁剪算法参考、优化后的 Python、独立 Rust。Python 优化参考与
Rust 均在 load 时缓存整数邻接及反向关系、路径/边 JSON 成本；查询按虚拟项成本
裁剪后才构造保留的循环组，不让只有 Rust 多做一项响应优化。

完整试验实际处理协议 JSON、图发布、源文件清单与哈希前后校验、SCC、层级、
完整事实裁剪、输出 JSON。双方处理相同预先解析/绑定/聚合的事实。共同字节客户端
计时包含传输和服务端处理，不计外部客户端请求编码、响应解码及准确性比较。
每项查询都有独立前后校验，包括一个传输批次中的每项。

这里的“完整”是固定快照只读图请求流程，生产的注册授权、忽略策略、SQLite
关系解码、MCP 包装、写入恢复及生命周期未迁移。不可用本结果声称整个 CoLink
已经迁移或获得同等倍数加速。此试点没有接入生产工具。

## 小函数混合调用的交叉区间

Python 在本进程计算，Rust 为常驻子进程；Rust 列包含每次通信、结果 JSON 编码、
Python 接收并解码。双方已缓存邻接，不重新发布图。每轮连续 8 次，交替顺序 5 轮，
以下为每次查询中位数；比较优化后的 Python，不用慢参考扩大 Rust 收益。

| 文件图节点 | 图来源 | Python，毫秒 | Rust 含通信/解码，毫秒 | 观测 |
| --- | --- | ---: | ---: | --- |
| 1 | 真实子图 | 0.000776 | 0.010260 | Python 更快 |
| 32 | 真实子图 | 0.009646 | 0.018208 | Python 更快 |
| 128 | 真实子图 | 0.045964 | 0.046604 | 基本持平 |
| 512 | 真实子图 | 0.257854 | 0.165724 | Rust 约 1.56 倍 |
| 1,024 | 真实子图 | 0.554677 | 0.323083 | Rust 约 1.72 倍 |
| 2,263 | 真实全图 | 1.339854 | 0.808057 | Rust 约 1.66 倍 |
| 10,000 | 合成图 | 4.403599 | 1.292161 | Rust 约 3.41 倍 |
| 50,000 | 合成图 | 22.486260 | 6.203057 | Rust 约 3.63 倍 |

可用的工程区间是：几十个节点的小函数直接留在 Python；百级属于过渡区；从本次
512 节点样本开始 Rust 的常驻混合调用出现明显收益；更大的合成图收益扩大。
交叉点只能夹在实际采样点之间，不是所有图都在 128 个节点处切换。结果还依赖边数、
循环结构、返回大小和进程是否常驻，不支持按文件数量单一硬切。

## 通信、校验、响应都由同一语言处理

metadata 模式每次完整遍历源码并核对身份、大小、纳秒 mtime/ctime、链接和目录
版本，仅在完整版本键相同时复用已验证哈希。它不是跳过源码校验。

SootUp 各点 5 轮，CPython 3 轮。以下均为常驻进程、独立请求的批次中位数，
单位毫秒；只有少量轮次，未把它们包装成可靠 P95。

| 128 | 1 | 6.005 | 4.619 | 23.1% |
| 1,024 | 1 | 21.989 | 15.570 | 29.2% |
| 2,263，SootUp | 1 | 56.569 | 40.968 | 27.6% |
| 2,263，SootUp | 8 | 427.077 | 306.538 | 28.2% |
| 2,263，SootUp | 64 | 3,398.268 | 2,468.192 | 27.4% |

| 2,082，CPython | 8 | 184.377 | 107.739 | 41.6% |

64 次 SootUp 实测吞吐为 Python 18.83 次/秒，Rust 25.93 次/秒。合并成一个
transport batch 也测试了 1/8 次，仍逐项前后校验，没有凭空得到数量级加速。
这些查询复用图，但没有复用查询结果。

实际改写一个副本源文件的 EOF 空白后，完整重新发布图，再做 8 次独立查询，共
3 轮：Python 完整组合中位数 581.014 毫秒，Rust 402.530 毫秒，耗时约少 30.7%。
单独发布阶段中位数为 137.619 / 82.326 毫秒；每轮修改内容、哈希与结果留存。
这不包含重新解析/绑定源码的成本，不能当作全仓增量索引加速。

## 每次全量哈希时的反转

strict 模式每个请求的前后校验都重新读取和 SHA256 全部源码，双方条件相同。

| 真实源码 | 请求数 | Python，毫秒 | 当前 Rust，毫秒 | 观测 |
| --- | ---: | ---: | ---: | --- |
| SootUp，约 6.98 MB | 1 | 127.942 | 124.725 | 约 2.5% 差异，视作接近 |
| CPython，约 33.54 MB | 1 | 102.160 | 178.598 | Python 约 1.75 倍 |
| CPython，约 33.54 MB | 8 | 813.649 | 1,434.660 | Python 约 1.76 倍 |

当前 Rust 依赖为 sha2 0.10.9 默认特性，本机 aarch64 构建未启用 asm；检查锁定的
依赖源码确认选中软件 SHA256 路径。Python hashlib 实际对象来自 _hashlib。
这是哈希实现/构建差异的直接证据；各项开销还未完整分摊，不能把整段反转全部归因
哈希库，更不能称为 Python 语言天生适合大文件。用户要求收尾后没有继续启用新
特性、重编译、复测或调参；后续如果推进，此后端选择必须先单独验收。

当前能给出的字节区间只有：这套构建在约 7 MB 全量读场景接近、约 33.5 MB 场景
Python 明显占优。7–33.5 MB 内的精确交叉点没有测定。

## 冷启动、内存与准确性

除首次启动外，Rust 启动到 ping 约 2.8–3.0 毫秒，Python 约 26–27 毫秒。首次
执行 Rust 观测到 598.8 毫秒，未分解原因，原始样本保留，没有丢弃。新二进制为
452,000 字节；不需要在终端用户机器上安装 Rust 编译器。

完整试验服务端峰值 RSS 并不总是 Rust 更低：SootUp 2,263 文件中优化 Python
约 87.5 MiB、Rust 约 96.4 MiB；CPython 约 65.1 / 69.7 MiB。这里是独立 worker
峰值，不含共同客户端，也不是保留 Python 协调器后的完整应用内存。这版 Rust
读取 JSON 和图 payload 时的副本仍有成本，不宣称已经证明内存下降。

各性能请求的完整结构响应逐项一致。旧 SCC/裁剪参考与优化版本、Rust 共用相同
事实；这证明计算/输出等价，不证明前端解析事实或运行时调用完全准确。SootUp
仍有 201 个 partial 文件；CPython 保留真实无效语法测试和排除文件说明。

少量关键边界还验证：同尺寸改写并恢复 mtime 仍被拒绝、新增源码被拒绝、符号链接
被拒绝、失败 load 保持原图；metadata/strict 均通过。Unicode/emoji/引号路径及
1,000/2,000/5,000 字符预算另有定向参考验证。没有大面积回归。

默认生产预算不足以导出本次全图：SootUp 默认仅 634 个合法观察节点、CPython
441 个；显式扩大私有评测预算才取得上述完整输入。扩大仅发生在试验实例，未改
生产默认；不能将本次图规模改写成当前产品已支持全仓相同覆盖。

分析处理链，避免每次启动进程或只跨语言调用极小函数。Python 的图缓存、预算
裁剪优化也有独立价值；Rust 正式替换前需处理 SHA 后端和 JSON/图发布内存副本。
