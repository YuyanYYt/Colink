# Colink 0.4.1 · 缺陷核验与改动范围

日期：2026-10-05。来源为用户提供的两份 ChatGPT 分析，结论以当前源码、测试和
实际客户端可见状态为准，不把 AI 提出的建议全部当成已证实的 Bug。

## 核验表

| 提出的点 | 核验结论 | 本轮处理 |
| --- | --- | --- |
| 第一次 `get_diff` 把完整项目当新增源码输出 | 确实存在，隐式空基线容易带来无关源码和上下文膨胀 | 无前次时返回 `NO_PREVIOUS_SNAPSHOT`；显式 `baseline="empty"` 才比较空目录 |
| 没有 previous 时引导重新获取 overview | 确实误导，刷新不能凭空生成历史 | 独立错误码，不再混同快照过期 |
| 项目只有内部 ID | 可用性缺口，不是源码同步失效 | 本机连接返回目录名作为 `display_name`，不暴露绝对路径；静态服务回退为 ID |
| 网页无法检查本机同步状态 | CLI 已有状态，MCP 没有此入口 | 增加 `connection_status`，不触发采集；明确完全离线时工具也无法回答 |
| diff 一上来返回大量补丁 | 有预算但缺乏摘要入口 | 默认摘要、文件分页，按需单文件补丁和可调字符预算 |
| 只保留两份状态可能中断长审查 | 已知取舍，符合用户磁盘偏好，不是可静默扩展历史的授权 | 保持两份，过期失败关闭；重新获取必要证据，不混用状态 |
| 看不到过滤规则，可能泄露敏感文件/符号链接 | 规则反馈不足；符号链接/常见密钥已有保护；服务账号文件名、大写 `.SSH` 确有缺口 | 状态工具展示规则；补基础敏感文件名和目录大小写过滤；否定规则不能解除强制排除 |
| overview 哈希字段冗余 | 确实默认返回逐文件哈希 | 默认隐藏，诊断可 `include_hashes=true`；内部同步哈希不变 |
| 文件清单没有树状层级 | 功能建议 | 保留路径分页，树状摘要留给后续重构 |
| 搜索区分大小写、没有 regex/符号语义 | 已声明的字面量搜索能力 | 不把它误称成 AST 查询，暂不扩展搜索协议 |
| 读取继续翻页不方便 | 有行号/has_more，但没有直接续页字段 | 增加 `next_start_line`，原读取上限不变 |
| 没有 AST/import/call 索引 | 尚未实现的增强能力 | 不属于本轮 bug 修复；由未来重构另定语言、范围和资源预算 |

## 回归方法和已经验证的边界

- 新增 `tests/test_mcp_workflow.py`，以独立临时人工样例检查初始 diff、各错误状态、
  固定目标/基线、摘要分页、显式补丁预算、名称、只读状态和敏感文件名。
- 改动前新增断言出现 8 个预期失败；其中既有真实缺陷，也有待添加功能的断言，
  不能解释为发现了 8 个同类严重 Bug。改动后相关 177 项通过。
- 最终全量 300 项通过；包含真实本机监听器起止状态的新增验证；已有存储、保留窗口、
  幂等、冲突、断网/重启恢复、扫描、
  同步、HTTP/stdio、应用监督关闭及打包拒绝覆盖测试均纳入全量。
- 原先在 `/private/tmp` 的首次全量受应用禁止系统目录的规则影响；改用项目内新的
  `.artifacts/test-runs/` 临时目录通过。没有为了通过测试放宽文件夹保护。
- `ruff check .` 与 `ruff format --check .` 通过。锁文件只更新 Colink 自身版本，
  第三方 Python 依赖不升级。Skill 使用官方创建技能校验脚本通过。
- 两套本机端到端 demo 通过，均发现 6 个只读工具；持续 stdio 验证源码更新与停机
  编辑恢复。它们不是 ChatGPT 网页的源码更新/自动 Skill 激活证据。

本轮无数据库 schema 或同步协议迁移，不改变两份保留策略，不操作用户真实源码。
查询仍不执行命令、不写源目录、不触发同步。

## 未宣称解决的限制

基础凭据过滤不是完整 DLP；嵌套 `.gitignore` 尚未处理。最多 8 MiB/10,000 文本文件、
单文件 1 MiB 的原限制保持。读取按行限制，极长单行仍可能占用较多上下文；大型复杂
diff 的计算时间尚未做长期/多机压力测量。这些列为后续资源预算和体验优化，不能称作
完整安全审计、性能保证或所有潜在缺陷已消失。

早期锚点阶段因用户保持锁屏先做本地部分；后续在线验证已完成工具刷新、账号内
Skill 创建/安装、无需手动选择技能的自然问答与充分代码反例，以及自带样例单行
更新后的读取和摘要。没有修改真实项目源码，未验证任意账号或每轮 Skill 正文加载，
详细公开结果见 [VALIDATION.md](VALIDATION.md)。
